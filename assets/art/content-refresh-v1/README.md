# 상어 SOS 지역과 수문 아트 적용 가이드

2026-10-02. 기존 상어 SOS의 밝은 3D 아트에 맞춰 지역 소개 이미지 2종과 수문·스위치 상태 SVG 4종을 제작했다. **아트만 준비한 묶음이며, 게임 소스와 수문 규칙에는 아직 연결하지 않았다.** 클로드 코드에서 R02 장치 구현 및 R04 화면 적용을 진행할 때 이 파일을 기준으로 사용한다.

## 파일과 용도

| 파일 | 형식 | 용도 |
|---|---|---|
| north-harbor.png | 1536×1024 PNG 원본 | 북항 지역 소개 카드, 구간 전환, 다음 지역 예고 |
| sluice-works.png | 1536×1024 PNG 원본 | 수문 시설 소개 카드, 구간 전환, 다음 지역 예고 |
| gate-closed.svg | 128×128, 투명 SVG | 닫힌 수문. 수평 셔터가 중앙을 막음 |

| switch-off.svg | 128×128, 투명 SVG | 비활성 스위치. 솟은 주황 버튼과 가로선 |

| preview.html | HTML | 두 지역과 32·48·64px 상태 비교용 독립 미리보기 |

## 시각 기준

원본 스타일 기준은 기존 `assets/icon-concepts/shark-sos-3d-v1-1024.png`와 `assets/art/shark-hero.webp`다. 기존 상어를 새로 생성하거나 교체하지 않는다. 둥근 아이보리 구조물, 아쿠아 반사광, 주황 장치, 짧은 접촉 그림자를 공유한다. 북항은 민트색 산책로, 수문 시설은 하늘색 구조물과 큰 주황 셔터로 구분한다.

지역 그림은 built-in ImageGen으로 제작했고, 작은 규칙 표시는 기존 프로젝트의 Canvas·SVG 표현에 맞춰 직접 작성했다. 외부 스톡 이미지·신규 폰트·추가 런타임 라이브러리는 사용하지 않았다. SVG에는 스크립트·외부 이미지·외부 글꼴·필터 애니메이션이 없다.

## 지역 이미지 적용

- 지역 선택·예고·전환 카드에서 3:2 비율로 표시한다. 기본 권장은 `object-fit: contain` 또는 같은 비율의 컨테이너다. 임의로 세로 화면 전체를 채우며 자르지 않는다.
- 글자는 이미지에 포함하지 않았다. 제목과 설명은 별도 HTML로 그림 아래에 배치한다. 작은 화면에서 물결 위에 본문을 겹치지 않는다.
- 이 그림은 실제 퍼즐판이 아니다. 이미지 속 배·튜브·스위치·수문을 실제 칸 또는 충돌 위치로 해석하지 않는다. 실제 게임판은 기존 격자와 장치 렌더링을 유지하고 팔레트의 지역색을 적용한다.
- 수문 시설 그림 속 스위치는 시설을 소개하는 장식이다. 플레이용 스위치는 규칙이 허용하는 물길 타일에 배치하며, 그림 속 산책로 위치를 따르지 않는다.
- PNG는 고해상도 제작 원본이다. 정식 통합 시 기존 sharp 내보내기 흐름으로 카드용 WebP를 파생하고 시각 확인 후 사용한다. 원본을 지우거나 덮어쓰지 않는다. 현재 묶음에는 WebP 파생 파일이 없다.
- 지역 예고와 구간 전환에 같은 원본을 재사용한다. 두 이미지를 매 프레임 디코딩하거나 게임판 전체에 그리지 않는다.

## 장치 정렬과 상태

- 네 SVG 모두 `viewBox="0 0 128 128"`, 기준점 `(64,64)`, 투명 배경이다. 한 칸의 좌상단에서 `drawImage(image, x*T, y*T, T, T)`로 그리는 기준이다. 그림이 차지하는 픽셀과 충돌 영역을 혼동하지 않는다.
- 수문 기둥은 모든 상태에서 같은 위치다. 기본 그림은 수평 셔터와 위아래 통행 방향이다. 좌우 통행용이면 칸 중심을 기준으로 90도 회전한다. 회전은 그림만 바꾸며 엔진 방향·충돌 설정은 별도로 일치시킨다.
- 열린 수문의 중앙은 완전히 투명하다. 닫힌 그림에 투명도만 낮추는 방식으로 대체하지 않는다.
- 스위치 상태는 색뿐 아니라 높이·버튼 크기·가로선/체크로 구분한다. 수문 상태도 실제 통로의 유무로 구분한다.
- 기본 연결 표식은 마름모다. 첫 구현의 단일 연결 그룹을 위한 아트다. 다중 그룹을 도입하면 색과 함께 다른 모양의 표식이 추가로 필요하다.
- `switch-on`이 모든 상황에서 `gate-open`과 같은 뜻은 아니다. 반대 상태로 연결된 수문 등 실제 연결 규칙이 생기면 각 장치의 엔진 상태에 따라 독립적으로 그림을 선택한다. 미리보기의 짝 전환은 아트 비교일 뿐 규칙 구현이 아니다.
- 32·48·64px를 미리보기에서 비교할 수 있다. 작은 기기에서는 모양 구분이 우선이며 조작이 필요한 버튼의 터치 영역은 별도 확보한다.
- SVG를 Image/Canvas로 읽거나 외부 img로 사용한다. 여러 복사본을 inline SVG로 넣는 경우 각 인스턴스의 gradient ID까지 고유하게 바꾼다.

## 구현 담당자에게 전달할 범위

1. 기존 CLAUDE.md와 현재 소스의 규칙을 먼저 확인한다. 이 아트 묶음은 스위치 발동 시점·수문 점유 처리·저장 스키마를 결정하지 않는다.
2. R02에서 수문 상태를 이동·구조정·풀이기·힌트·되돌리기·이어하기·장치 예시에 일관되게 반영한다.
3. R04에서 필요한 자산만 연결한다. 현재 `tools/build-source.js`는 기존 상어 WebP만 내장하므로, 새 파일을 폴더에 놓았다는 이유만으로 배포물에 포함된다고 가정하지 않는다.
4. 단일 HTML·아티팩트·PWA·Capacitor 각 빌드에 필요한 파일 또는 data URL을 포함하고, PWA 캐시 변경을 처리한다. preview.html과 이 가이드, 고해상도 원본은 게임 시작에 필요한 자산으로 묶지 않는다.
5. 로딩 실패 시 수문은 엔진 상태에 맞는 닫힌 막대/열린 기둥, 스위치는 단순한 상태 표식으로 대체한다. 이미지 실패로 길이 열린 것처럼 보이지 않게 한다.
6. 상태 전환 효과는 기존 프레임 루프를 사용하고, 동작 줄이기에서는 새 상태를 즉시 표시한다. 아트 안에 반복 애니메이션이나 새 타이머를 넣지 않는다.

## 확인 범위

실제 파일 크기와 SHA-256 해시는 manifest.json에 기록했고 원본과 대조했다. SVG 4종의 XML·내부 참조를 검사했다. 브라우저의 기본 데스크톱 화면과 360px 모바일 뷰포트에서 이미지 로딩, 32·48·64px 표현, 상태 비교 버튼의 양방향 전환, 가로 넘침 없음을 확인했다. 미리보기의 브라우저 오류 로그는 없었다.

기존 48개 수로 검증(`npm run verify`)과 두 빌드(`npm run build`, `npm run build:artifact`)도 통과했다. 새 아트는 실행 소스에 연결하지 않았다. 이번 묶음은 실제 퍼즐판 통합·충돌 판정·수문 해법·실물 Android 검증 완료를 의미하지 않는다.

미리보기는 저장소 루트에서 `node tools/serve.js . 5184` 실행 후 `http://127.0.0.1:5184/assets/art/content-refresh-v1/preview.html`로 확인할 수 있다. 또는 로컬 preview.html을 브라우저로 연다.
