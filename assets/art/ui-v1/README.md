# 로비 버튼 아트 v1

2026-10-03. 상어 SOS의 입체 상어·구명튜브와 어울리도록 기존 선 아이콘을 3D 토이 소품으로 교체했다.

| 파일 | 적용 위치 | 디자인 |
| --- | --- | --- |
| challenge.webp | 오늘의 도전 | 주황 깃발·크림 깃대·아쿠아 받침 |
| free.webp | 자유 수로 | 아쿠아/민트 파도·둥근 크림색 포말 |
| map.webp | 수로 선택 | 접힌 크림 지도·청록 물길·주황 목적지 핀 |
| journal.webp | 구조일지 | 민트 수첩·입체 구명튜브·노란 책갈피 |
| settings.webp | 메인/게임 설정 | 둥근 아쿠아 톱니·크림색 안쪽 테두리 |

제작: **built-in ImageGen**, 아이콘별 독립 호출 5회, 모두 실제 투명 배경 요청. 상어 대표 이미지 `../shark-hero.webp`의 색과 재질을 시각적으로 확인하고 같은 광원·둥근 재질을 명세했다. 외부 다운로드 자산이나 새 유료 라이브러리는 사용하지 않았다. 전체 호출 명세는 [PROMPTS.md](PROMPTS.md)에 보관한다.

- `source/*.png`: 생성 원본 보존. 덧칠하거나 배경을 합성하지 않는다.
- `*.webp`: 각 192×192. 작은 버튼의 고해상도 화면에 대응하며 투명 경계를 유지한다. 5개 합계 47,912 bytes.
- [manifest.json](manifest.json): 원본/납품 SHA-256, 실제 추출 경계, 크기, 용량.
- `tools/prepare-ui-art.js`: alpha 검사 → 실루엣과 여유 2px 추출 → 최대 174px로 축소 → 192px 투명 정사각형 중앙 정렬. 그림의 비율과 내용은 유지한다.

```powershell
node tools/prepare-ui-art.js <기존 sharp 설치 경로>
```

`tools/build-source.js`가 `src/art.js`의 URL 목록에 다섯 자산을 한 번씩 내장한다. `MENU_ART.load()`는 각 `[data-menu-art]` 위치에 장식용 빈 alt 이미지를 한 번만 연결한다. 브라우저 이미지 캐시를 사용하고, 프레임 루프에 이미지 생성·필터·합성을 추가하지 않는다. 로드 전과 실패 시에는 기존 SVG가 보이며 버튼의 이름·클릭 영역·연결은 그대로다. 메인과 게임 설정은 같은 URL을 공유한다.

`내 상어`는 현재 선택한 스킨을 그리는 기존 `skinPreview` Canvas와 스킨 이름·저장 처리를 유지한다. 기존 단일 HTML·아티팩트·웹/PWA의 내장 방식과 오프라인 동작도 유지한다.

## 검증

- 자동 검사 137개 통과. 기존 빌드 내장 검사에 5개 파일의 해시/내장 여부를 추가했고, 메뉴 이미지의 중복 로딩 방지·정상 로드·실패 대체 검사를 추가했다.
- 스토리 48개와 시험 코스 12개 해법 검증, 단일 HTML·아티팩트·웹 빌드 통과.
- 5개 WebP 모두 가장자리가 투명하고 잘림이 없음을 검사했다. 글꼴 누락 경고 없음.
- 브라우저 320×568 및 390×844에서 선명도·아이콘과 제목 간격·가로 넘침을 확인했다. 320px에서 세 바로가기는 기존과 같이 약 556px 안에 표시된다.
- 일일·자유·구조일지·설정·내 상어 열기/닫기 및 포커스 복귀, 수로 선택 펼침, 이어하기와 게임 설정의 같은 아이콘 표시를 확인했다.
- 별도 로컬 QA 페이지에서 다섯 이미지 URL을 모두 실패시키고, 기존 SVG 표시와 설정 열기/닫기를 확인했다. 이 QA 변경은 배포 빌드에 포함하지 않는다.
- 비교 화면: `outputs/qa/menu-art-before-390.png`, `menu-art-after-390.png`, `menu-art-after-320.png`, `menu-art-failure-320.png`.

브라우저 검증이며 실제 휴대폰 터치·네이티브 APK/AAB 재빌드 검증은 포함하지 않는다.
