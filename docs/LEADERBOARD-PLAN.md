# 순위표 계획 — Google Play 게임즈

상태: **계획.** 사용자 결정(2026-10-08):

- 방식: Google Play 게임즈 서비스(Android 앱 전용)
- 순위 기준: 오늘의 작전 · 연속 구출 일수 · 자유 수로 완료 수
- 시점: 출시 후 첫 업데이트. 10월 17일쯤 프로덕션 신청은 순위표 없이 진행한다.

## 1. 왜 Play 게임즈인가

- 로그인 화면을 만들지 않는다. Play 게임즈 프로필로 자동 로그인하고, 순위표 화면은 Google이 제공한다.
- 우리 서버, 회원 데이터, 계정 삭제 기능이 필요 없다.
- 웹(GitHub Pages)·PWA에는 순위표가 없다. 앱에서만 순위표 버튼을 보여 준다.

## 2. 먼저 해 주셔야 하는 것 (Play Console)

계정·콘솔 설정은 직접 해 주셔야 한다. 메뉴 이름은 콘솔 화면 기준으로 확인한다.

1. Play Console의 이 앱(`kr.hongrae.sharksos`)에서 **Play 게임즈 서비스** 설정을 시작하고, Google Cloud 프로젝트를 연결한다.
2. **사용자 인증 정보**: Android 사용자 인증 정보를 패키지 이름 `kr.hongrae.sharksos`로 만든다. SHA-1은 두 가지를 모두 등록한다(내려받은 앱과 직접 설치한 빌드가 모두 로그인되게).
   - Play 앱 서명 키: 앱 무결성 화면
   - 업로드 키: `~/.android-keys`
3. **순위표** 3개를 만든다. 정렬은 모두 '높을수록 좋음'이다. 만든 뒤 순위표 ID를 알려 주시면 코드에 넣는다.

   | 순위표 | 점수 | 비고 |
   |---|---|---|
   | 오늘의 작전 | 아래 4절 | 하루 단위 비교 방식 확인 필요 |
   | 연속 구출 | 연속 참여 일수 | 전체 기간 |
   | 자유 수로 구출 | 자유 수로 누적 완료 수 | 전체 기간 |

4. 게임 서비스 **테스터**에 본인 계정을 넣는다. 게시 전에는 테스터만 순위표를 볼 수 있다.
5. 앱과 함께 게임 서비스 설정을 **게시**한다.

## 3. 앱 구현 (첫 업데이트)

- **네이티브:** Play 게임즈 v2 SDK를 Android 프로젝트에 추가한다.
  - `Launchpad.java`처럼 작은 Capacitor 플러그인 하나로 다음을 연다: 로그인 확인, 점수 제출, 순위표 열기.
  - 외부 Capacitor 플러그인은 쓰지 않는다(의존성 최소화).
- **게임:** 플러그인이 있을 때만 메인·일일·자유 시트에 순위표 버튼을 보여 준다.
  - 점수는 일일 작전 완료와 자유 수로 첫 탈출 때 보낸다.
  - 실패해도 게임과 저장에는 영향이 없다.
- **개인정보:** Google로 점수를 보내므로 `privacy.html`과 Play 데이터 보안 신고를 고친다.

## 4. 점수 설계와 정할 것

- **오늘의 작전:**
  - 세 수로를 모두 마쳤을 때 `별 합계 × 1000 − 이동 합계`로 계산한다. 별이 먼저, 같으면 적은 이동이 앞선다.
  - 일일 판이 진행 단계에 따라 다를 수 있어, **장치를 모두 배워 표준 판을 받은 날**(`save.dailyDevices`가 모든 장치를 포함)만 제출한다.
  - Play 게임즈의 '오늘' 구간이 한국 날짜(자정)와 맞는지 구현 전에 확인한다. 맞지 않으면 '이번 주 별 합계' 순위로 바꾼다.
- **연속 구출:** 오늘의 도전 연속 참여 일수(`dailyStreak()`)를 낸다. Play 게임즈는 최고 기록을 유지하므로 끊겨도 순위가 내려가지 않는다.
- **자유 수로 구출:** `save.free.completed` 합계를 낸다.
- **조작 방지:** 점수는 기기에서 계산해 보낸다. 작은 게임이라 별도 검증 서버는 두지 않는다.

## 5. 검증

- 실제 기기나 Play 게임즈가 설치된 에뮬레이터, 내부 테스트 트랙에서 확인한다.
  - 로그인
  - 세 순위표 제출과 표시
  - 오프라인일 때의 동작
  - 로그인을 거절했을 때 버튼 숨김
- 웹 빌드에는 순위표 버튼이 나오지 않는지 확인한다.
