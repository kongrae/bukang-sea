## 장치를 고른 과정

새 장치 후보 6개를 실제 엔진 사본으로 시제품까지 만들었다. 견본 수로를 만들고, 최소 이동·탐색 상태·장치 필요성(반사실 검사)·무작위 3별 비트를 측정했다. 평가는 플레이어·유지보수·회의론 세 관점으로 했다.

| 후보 | 규칙 요약 | 평가(10점) | 판단 |
|---|---|---|---|
| **나무 상자** | 부딪히면 끝까지 밀려남 | 7–8 | 채택. 판 자체를 바꾸는 첫 장치 |
| 미역 숲 | 지나가면 닫혀 벽이 됨 | 5.5–6 | 안전하지만 '되돌아와 멈추기' 하나로 수렴하고, 그물·모래톱과 겹침 |
| 오륙도 물때 바위 | 이동마다 잠김·드러남 | 3–4.5 | 홀짝 세기 퍼즐이고, 6장 수문과 체감이 비슷함. 8장 이후 후보 |
| 물턱(한쪽 통과) | 한 방향으로만 넘음 | 3–5 | 얕고 6장 수문 자리와 같음. 보조 재료 |
| 모자반 더미 | 부딪히면 흩어짐 | 3.5–5 | 상자의 하위 호환 |
| 회전 가름판 | 지나가면 도는 반사판 | 4–4.5 | 34px 칸에서 예측이 어려움 |

1–6장 장치는 모두 '고정된 판 위에서 길 찾기'다. 상자는 처음으로 상어가 판을 바꾸는 장치다. 상자도 상어처럼 '막힐 때까지 미끄러진다'는 한 문장으로 설명된다.

## 규칙 (`src/engine.js`가 기준)

- 맵 글자는 `c`이고, 수로당 최대 2개다. 상자가 있는 칸은 물이다. 상어와 구조정에게 상자는 부표처럼 막는 칸이다. 상자 칸에는 그물을 칠 수 없다.
- **밀기:** 다음 조건을 모두 만족하면 상자가 같은 방향으로 막힐 때까지 미끄러진다.
  - 상어가 한 칸 이상 헤엄쳐 왔다.
  - 상자에 부딪혀 멈췄다(`slide().stop === 'block'`, 물줄기·소용돌이를 거친 마지막 방향 바로 앞이 상자).
- **상자가 들어가는 칸:** 그물·턴 시작 시점의 구조정·다른 상자·이번 이동 뒤에도 남은 숭어가 없는 `.`·`s` 칸만 들어간다. 모래톱 위에서는 멈춘다. 출구·물줄기·소용돌이·스위치·수문 칸에는 들어가지 않는다.
- **밀리지 않는 경우:** 연쇄 밀기는 없다. 붙은 채 스와이프하면 막힌 스와이프로 처리해 이동으로 세지 않는다. 모래톱이나 루프 방지로 멈췄을 때, 탈출했을 때도 밀지 않는다.
- **한 턴의 순서:** 미끄러짐 → 숭어 → (탈출이면 끝) → 상자 → 스위치 → 구조정. 밀린 상자는 바로 구조정을 막는다.
- **풀이기:** 탐색 상태에 상자 위치를 넣는다(`crateKey`). 상자 없는 수로는 키가 `''`라 탐색 순서·해법·별 기준이 이전과 같다.
  - `plan`/`planSearch`는 `pickup` 뒤 10번째 인자로 상자를 받는다.
  - 그물 지연 설치 가지치기에는 '이번 스와이프에서 밀린 상자가 지나갈 칸'을 더했다.
  - 이전 그물 규칙(일일·자유 v1–v3)의 탐색에 상자가 있으면 오류를 낸다.

## 게임 연결

- `st.crates`는 상자 수로에만 생긴다. 되돌리기·저장·복원에 포함하고, 잘못된 세션(중복, 물이 아닌 칸, 상어·구조정·그물·남은 숭어와 겹침)은 버린다. 상자 없는 수로의 상태·세션 형식은 그대로다.
- **연출:** 상어 도착 → 상자 0.16–0.22초 → 수문 → 구조정. 동작 줄이기에서는 도착할 때 최종 상태를 보여 준다.
  - 붙은 채 밀면 상자가 '툭' 흔들리고 이동 수는 늘지 않는다.
  - 소리는 기존 녹음(softImpact2·waterSwish, 멈출 때 woodCreak)만 쓴다.
- 힌트, 갇힘 안내, 첫 이동 안내 모두 현재 상자 위치로 탐색한다.
- 장치 안내에는 6.6초 예시 영상을 붙였다. 처음 만날 때 자동으로 재생된다.
- 범례·장 표지 칩·새 장치 칸 강조를 추가했다.
- 7장은 스토리 전용이다. 6장 수문처럼 일일·자유 생성기에는 넣지 않아서 `DAILY_OPERATION_VERSION`·`FREE_VERSION`은 그대로다. `learnedDevices()`에 `crate` 키가 늘어도 생성 결과는 같다.

- 장 평균 최소 이동은 9.6이고, 84번(18번 이동)이 게임에서 가장 긴 수로다.
- 무작위 3별 비트(`npm run difficulty -- --fixed-nets`, 이번에 수문·상자를 반영하도록 고침)는 2.5, 4.3, 11, 9.8, 11.3, 7.9, 10.9, 11.6, 12.4, 12.6, 7.7, 23.6이다.
- 숭어를 잃는 상태 비율(verify 기준)은 81번 5.3%, 82번 13.6%다. 나머지는 2% 이하다. 시제품 단계에서 우려했던 높은 교착률(일반판 20–40%)은 설계 단계에서 걸러 냈다.
- '출구 앞 칸에서 상자 치우기'만으로 끝나는 판은 없다.
- 모든 상자는 꼭 필요하다(`verify`가 확인): 부표로 바꾸거나 물로 바꾸면 숭어를 모두 먹는 길이 사라지거나 최소 이동이 바뀐다. 80·81번은 상자를 부표로 고정하면 오히려 짧아진다. 즉 '처음 밀고 싶은 방향'을 참는 것도 퍼즐의 일부다.

## 검사 (`npm run verify`)

상자 수로에만 다음을 확인한다.
- 그물 0개, 구조정 1척 이하.
- 상자마다 반사실 검사(부표·물로 바꾸기).
- 그물 없이 시작점에서 도달하는 상태 수 10만 이하.
- 연습판의 탈출 불가 상태 0개.
- 최적 경로가 한 번 이상 민다.

도달 상태·탈출 불가·숭어 잃음 비율과 밀기 횟수를 출력한다. 7장 수로도 벽 배치가 다른 모든 수로와 다른지 검사한다. 해법 재생(`tools/replay-plan.js`)과 장치 사용 판정(`varietyRouteUse`)은 `turn()`으로 상자를 이어 간다.

## 이어 하기·엔딩

- 6장을 끝낸 기록은 7장 첫 수로를 바로 연다(기존 `unlocked()` 규칙). 6장 끝 결과창은 '수문 시설 통과!'와 7장 미리보기를 보여 준다.
- 7장이 들어온 뒤 처음 실행할 때 `migrateStoryLength()`가 판정한다. 72개를 이미 모두 탈출한 기록이면 `storyRescued: 1`을 남겨 엔딩 다시 보기를 유지한다. 판정은 한 번뿐이다(`save.storyLength`에 마지막 실행 때 이야기 길이를 저장, 필드가 없던 저장은 72로 본다). 그래서 이 빌드에서 72번까지 처음 도착한 이용자에게 엔딩이 미리 열리지 않는다. 메인 버튼은 '이어서 구출!'로 7장을 안내한다. 장을 더 늘려도 같은 규칙이 그대로 적용된다.
- 6장 소개·마무리 문구와 6장 마지막 수로의 안내를 이야기가 이어지게 고쳤다. 엔딩은 7장 끝에서 열린다.

## 리뷰 후 수정

여러 관점의 코드 리뷰 뒤, 반박 검증을 통과한 지적을 고쳤다.
- 기록에서만 계산하던 엔딩 유지는 새 이용자가 72번에 도착해도 엔딩을 열었다. 그래서 위의 1회 판정으로 바꿨다.
- 물줄기 칸에서 상자에 부딪힐 때 상어가 들어온 방향을 보던 것을, 상자 쪽(엔진의 마지막 방향)을 보게 했다. 상자 없는 물줄기 정지는 이전과 같다.
- `difficulty.js`(고정 그물 bits)와 `variety-audit.js`(경로 재생)가 상자·수문을 무시하던 것을 `E.turn`으로 고쳤다. 상자·수문이 없는 수로의 결과는 이전과 같다.
- 물고기를 먹은 직후 0.12초 안의 상자 소리는 기존 '획득음 우선' 규칙대로 생략된다(의도된 동작, 판이 밀리는 모습은 그대로).
