작성일: 2026-10-08. 작업 폴더: `C:\workspace\bukang-sea`. 상태: 인수 문서(미착수).

에이전트에게 이렇게 요청한다.

> `docs/SOUND-MOTION-HANDOFF.md`를 읽고 FX01부터 진행해줘. 사람이 들어 봐야 하는 단계에서는 비교 페이지를 만들어 알려 주고, 내가 고를 때까지 그 소리는 게임에 적용하지 마.

이 문서는 이 저장소에서 작업하는 에이전트(Claude Code, Codex 등)에게 넘기는 작업 지시다. 시작할 때 Git 상태와 최신 소스를 다시 확인한다. 이 문서의 기록을 근거로 현재 변경을 되돌리지 않는다. `.claude/` 등 미추적 파일과 사용자의 미커밋 변경을 보존한다.

## 목표

상어 SOS의 손맛을 **실제 출시 게임에서 쓰는 방식**에 맞춰 풍부하게 만든다. 손맛은 밀었을 때의 반응, 숭어 획득, 장치 작동, 구출 완료의 느낌을 말한다.

1. 효과음은 코드로 합성한 소리와 AI 생성 오디오 대신, **사람이 녹음·제작하고 라이선스를 확인한 음원**으로 바꾼다. 현재 합성음은 디코드 실패 때의 대체음으로만 남긴다.
2. 연출은 애니메이션 1–8의 결과를 유지한다. 실제 게임 사례와 비교해 빠진 부분만 보강한다.
3. 판단 근거는 개발자 인터뷰·강연·공식 영상처럼 확인할 수 있는 출처로 남긴다. 출처 없는 '실제 게임은 이렇다'는 주장으로 결정하지 않는다.

## 지켜야 할 규칙

- **AI 생성 오디오 금지.**
  - 생성 모델(텍스트를 효과음·음악으로 바꾸는 서비스 등)로 만든 소리와, 생성 여부를 확인할 수 없는 소리를 쓰지 않는다.
  - Freesound는 2026-07부터 업로더가 생성 AI 사용을 표시할 수 있다. 다만 2026-09 기준으로 검색에서 걸러 주지는 않는다.
  - 소리마다 페이지를 열어 표시와 설명을 확인한다. 표시가 있거나 녹음 방법이 불분명하면 제외한다.
- **실제 게임의 소리·이미지를 추출하거나 녹음해 쓰지 않는다.** 참고하는 것은 설계 방식(층 구성, 길이, 음높이 변화, 타이밍, 변형 수)뿐이다.
- **라이선스.** 저장소는 GitHub `kongrae/bukang-sea`에 있고 GitHub Pages로 웹 배포하므로 공개 저장소로 간주한다(시작할 때 확인).
  - 기본 허용: CC0. 원본과 가공본을 저장소에 넣을 수 있다.
  - CC-BY: 크레딧 표시 위치(예: 설정 → 정보)를 정하고 사용자 승인을 받은 뒤에만 쓴다.
  - 금지: 비상업(NC), 출처·라이선스 불명, 효과음 파일의 재배포를 금지하는 라이선스.
  - 예: Sonniss #GameAudioGDC 번들(라이선스 v2.0, 2026-08-27 시행)은 상업 이용과 크레딧 생략을 허용한다. 하지만 효과음을 파일로 공급하는 것은 금지한다. 공개 저장소에 넣는 것이 여기에 해당할 수 있어 사용자 결정 없이는 쓰지 않는다.
- **바꾸지 않는 것:**
  - 게임 규칙·레벨·별 기준·저장 형식·힌트 정책·스킨 조건.
  - 일반 헤엄 출발·정지 소리(사용자 요청으로 제거)와 화면 흔들림·진동 연출(2026-09-30 제거)은 다시 넣지 않는다. 필요하다고 판단되면 제안만 한다.
  - 배경음악은 범위 밖이다.
- **기존 동작 유지:**
  - `save.sound` 설정과 음소거, 화면 이탈·백그라운드 정리, 보상음 예약 취소, 동작 줄이기, 대기 입력 1개 규칙.
  - 프레임 상한(짧은 활성 이동은 화면 콜백, 대기 30회/초).
  - 연출 때문에 입력을 막거나 늦추지 않는다.
- **의존성:** 게임 런타임에 라이브러리를 추가하지 않는다. 음원 가공에 ffmpeg 같은 개발 도구가 필요하면 설치 전에 사용자에게 묻는다. 2026-10-08 기준 이 PC에는 ffmpeg·sox·lame이 없다.
- **청취 한계:** 에이전트는 브라우저 스피커 출력을 들을 수 없다(`docs/SOUND-DESIGN.md`). 파형·길이·피크 수치는 검사할 수 있지만 '듣기 좋다'는 판단은 사용자가 한다. 들어 보지 않은 소리를 좋다고 보고하지 않는다.

## 현재 상태 (2026-10-08)

- **`src/sound.js`:** Web Audio 합성 세트다. 이동·정지는 무음이다. 이벤트는 다음과 같다.
  - 플레이: `bump`(막힘), `eat(complete, chain)`(숭어, 한 이동 안에서 A4–C5–D5–E5 상승), `net(remove)`
  - 장치: `jet`, `warp`, `sand`, `press`(스위치), `gate`, `boat`
  - UI: `undo`, `ui`, `start`, `equip`, `sheet(opening)`
  - 결과·보상: `exit`, `win`, `star(index)`, `unlockReward`
- **재생 관리:**
  - 컨텍스트·노이즈 버퍼 재사용
  - 동시 효과 6개(교체 중 8개 이하), 이벤트별 간격 제한, 획득·보상 우선
  - 공통 3.4kHz 저역 통과와 ±1.25% 피치 변주
  - 음소거 시 현재 음과 예약 음 정지
- **비교실:** `npm run build:sound-lab`가 `outputs/audio/`에 행동별 전후 재생, WAV, 파형 검사, 기록 격리 5분 자동 플레이를 만든다.
- **연출:** 애니메이션 1–8을 완료했다(별·해금·도장·스킨 보상, 이동·정지·장치 반응, 메인, 시트, 성능·동작 줄이기). 실물 Android 검증은 남아 있다.
- **외부 오디오 파일:** 0개다. 그림은 `tools/build-source.js`의 `ART` 목록으로 data URL에 내장하지만, 오디오를 내장하는 경로는 없다.
- **장 구성:** 장마다 새 장치 하나, 6장 × 12 = 72개다(`docs/CHAPTER-RESTRUCTURE.md`).

### FX01 조사·설계

- 위 사례를 다시 확인하고, 조사 후보 중 근거를 찾은 사례만 추가한다.
- 이벤트별 사양표를 만든다. 열은 다음과 같다.
  - 이벤트, 현재 소리·연출, 참고 사례와 근거
  - 목표 느낌(예: '젖은 고무가 톡'), 길이(ms), 층 구성, 변형 개수
  - 우선순위·동시 재생 상한, 동작 줄이기·음소거 때 처리
- 대상 이벤트:
  - 플레이: 막힘, 숭어(연속·마지막), 그물 설치·회수, 되돌리기
  - 장치: 물줄기, 소용돌이, 모래톱, 스위치, 수문, 구조정
  - 결과·보상: 탈출, 별 1–3, 새 스킨 해금, 장 통과
  - UI: 시작·버튼·시트
- 장마다 새 장치가 하나씩 나오는 구조이므로 장치 소리끼리 쉽게 구별되게 한다.
- 결과는 `docs/SOUND-MOTION.md`(새 문서)에 기록한다.

### FX02 음원 후보 수집·가공

- **후보 선정:** 이벤트마다 후보 2–3개를 고른다.
  - 밝은 아쿠아·토이 톤, 짧은 어택
  - 길이 0.05–0.6초(보상음은 1.2초 이하)
  - 작은 볼륨의 휴대폰 스피커에서도 구별되는 중고역
- **가공:** 앞뒤 무음 자르기, 5–10ms 페이드, 모노, 44.1/48kHz, 피크 −1dBFS 이하, 그룹별 음량 맞춤(획득·보상 > 장치 > UI).
- **형식:** Android WebView·Chromium의 `decodeAudioData`에서 실제로 디코드되는지 확인한다. iPhone Safari까지 고려하면 MP3(CBR) 또는 AAC가 가장 안전하고, Ogg는 Safari 지원이 불확실하다. 디코드에 실패하면 합성음으로 대체한다.
- **파일 위치:** 원본(CC0)은 `assets/audio/source/`, 가공본은 `assets/audio/`, 출처 기록은 `assets/audio/LICENSES.md`(또는 JSON)에 둔다.
- **용량:** 기본 상한은 내장 오디오 합계 400KB 이하(base64 포함)다. 넘으면 변형 수를 줄이거나 비트레이트를 낮추고 보고한다.

### FX03 청취 비교실 (사용자 확인 필수)

- 기존 `npm run build:sound-lab` 비교실을 확장한다.
  - 행동별로 현재 합성음과 후보 A/B/C를 재생한다.
  - 실제 게임 순서(이동 → 숭어 3마리 → 장치 → 탈출 → 별 3개)로 이어 듣는 버튼을 둔다.
  - 휴대폰에서도 열 수 있게 `--host` 실행 방법을 안내한다.
- 사용자에게 비교 페이지 주소를 알리고 행동별로 하나씩 골라 달라고 요청한다. 고르기 전에는 해당 소리를 게임에 적용하지 않는다.
- 선택 결과를 `docs/SOUND-MOTION.md`에 기록한다.

### FX04 적용

- **재생 경로:** `src/sound.js`에 음원 재생 경로를 추가한다. 첫 사용자 입력 뒤에 디코드하고, 디코드한 `AudioBuffer`를 캐시한다. 기존 `effect`의 우선순위·상한·간격 제한·음소거·중단·예약 취소를 그대로 적용한다.
- **변형과 음높이:**
  - 같은 변형이 연속으로 나오지 않게 순환하고, 피치 변주는 작게 유지한다.
  - 숭어 연속 상승은 음원의 재생 속도나 음별 음원으로 같은 음계를 유지한다. 마지막 숭어는 별도 층으로 강조한다.
- **빌드 내장:**
  - `tools/build-source.js`에 오디오 data URL 내장을 추가한다. 단일 HTML·아티팩트·웹/PWA·Capacitor에서 같은 소리가 나야 한다.
  - PWA 캐시 해시에 반영되는지 확인한다. 네트워크 오디오 요청은 없어야 한다.
- **합성음:** 코드를 지우지 않고, 디코드 실패·미지원 시 대체음으로 남긴다.

### FX05 연출 보강

- 애니메이션 1–8의 현재 동작을 실제 게임 사례와 비교해 빠진 것만 고른다. 후보 예:
  - 숭어를 먹으면 작은 숭어 아이콘이 HUD의 숭어 목표로 날아가고 숫자가 살짝 튀는 연출
  - 장의 새 장치가 처음 나오는 수로에서 그 장치 칸을 한 번 강조하는 연출
  - 탈출 순간 출구 쪽 물보라 강화와 결과 시트 직전의 짧은 멈춤(입력 지연 없이)
  - 장 통과 때 여정의 다음 장으로 이어지는 연출
- 항목마다 근거 사례, 길이, 동작 줄이기 처리, 성능 영향(프레임 상한 유지)을 적는다. 이미 있는 연출을 중복으로 만들지 않는다.
- 새 그림 파일이 필요하면 용도·크기·상태를 목록으로 남기고 사용자에게 알린다.

### FX06 검증·문서·커밋

- **자동 검사 추가:**
  - 음원 디코드 실패 시 합성음으로 대체되는지
  - 음소거 시 음원 소스가 멈추는지
  - 같은 변형이 연속으로 나오지 않는지
  - 동시 재생 상한이 지켜지는지
  - 내장 오디오의 개수·용량이 상한 안인지
  - 출처 기록 누락이 없는지: 모든 파일에 CC0 또는 승인된 라이선스, 원본 URL, AI 아님 근거가 있어야 한다
- **렌더링 검사:** Chromium `OfflineAudioContext`로 기존 13초 순서와 5초 밀집 순서를 다시 렌더링해 피크·클리핑·종료 후 남은 소스를 확인한다.
- **실행:** `npm test`, `npm run verify`, `npm run build`, `npm run build:artifact`, `npm run build:web`(폰트 누락 경고가 나오면 `npm run fonts`), `npm run build:sound-lab`.
- **브라우저:** 콘솔 오류 없음, 오디오 네트워크 요청 없음, 음소거·백그라운드·복귀, 동작 줄이기를 확인한다.
- **문서:** `docs/SOUND-DESIGN.md`(현재 기준으로 갱신), `docs/SOUND-MOTION.md`, `CLAUDE.md`의 사운드 설명('외부 오디오 파일 없음' 문구 갱신), `docs/ANIMATION-ROADMAP.md`.
- **커밋:** `CLAUDE.md` 규칙대로 한다(src를 바꾸면 dist 재빌드 포함, `.claude/` 제외). Android 빌드·Play 업로드는 별도 지시가 있을 때만 한다.
