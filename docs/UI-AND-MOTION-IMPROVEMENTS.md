# 바텀시트 조작과 상어 이동 개선

2026-10-03. 요청한 두 작업을 함께 구현했다. 비교 기준은 `df9bad924ef064893d3e351e865bd03323ce8b50`이다. 기존 애니메이션 1–8의 후속 보완이며 새 콘텐츠 번호를 추가하지 않는다.

## 원인

- 시트 손잡이는 `.card::before`로 그린 장식이었다. 시트의 포인터 드래그 처리가 없어 웹과 앱 모두 아래로 밀어 닫을 수 없었다.
- 게임의 60회/초 제한은 직전 그리기 이후 시간이 기준보다 짧으면 건너뛰고, 그린 시점으로 기준을 다시 잡았다. 일정한 90Hz 콜백에서도 45회/초, 144Hz에서는 48회/초로 줄어드는 문제가 재현됐다. 60Hz 근처의 불규칙한 콜백에서도 이동 프레임을 건너뛸 수 있었다. 이는 확인한 원인이며 모든 환경의 끊김 원인을 확정한 것은 아니다.

## 시트 동작

- 여정·엔딩·오늘의 구조작전·자유 수로·시험 코스·구조일지·내 상어·설정·장치 안내, 총 9개에 공통 드래그를 적용했다. 각 화면의 기존 닫기 함수를 호출하므로 생성 취소, 미리보기 정리, 안내 확인, 일일 작전/결과로 돌아가는 동작을 유지한다.
- 실제 손잡이 영역은 높이 44px이다. 손잡이와 제목에서 아래로 끌 수 있고, 본문 스크롤과 버튼 조작은 드래그 시작에서 제외한다. 헤더와 44px 닫기 버튼을 스크롤 중에도 표시한다. 작은 화면의 가로 넘침과 긴 콘텐츠의 축소도 보완했다.
- 10px 이상 움직였고 아래 방향이 가로 방향의 1.2배 이상일 때 드래그를 시작한다. 닫힘 거리는 시트 높이의 25%이며 최소 80px, 최대 160px이다. 최근 100ms 구간에서 0.65px/ms 이상으로 아래로 밀었으면 32px부터 닫힌다. 잠깐 들었다 놓거나 오래 잡고 있던 작은 이동은 닫히지 않는다.
- 카드는 포인터를 따라 내려가고 배경은 점차 옅어진다. 기준에 못 미치면 160ms 동안 제자리로 돌아온다. 닫힐 때는 놓은 위치부터 퇴장하며 입장 애니메이션이 다시 실행되지 않는다.
- 드래그 직후 생성되는 클릭, 다른 포인터, 포인터 취소/캡처 해제, 크기 변경, 시트 교체, 앱 중단을 정리한다. 배경 게임의 이동 입력과 시트 드래그가 겹치지 않는다. 포커스 복귀와 Tab 순환도 유지한다.
- 폭과 높이가 모두 640px 이상인 중앙 팝업에서는 손잡이를 숨기고 드래그를 끈다. 닫기·배경·Escape의 기존 동작을 사용한다. 클리어 결과는 다음/다시 하기의 명시적 선택이 필요하므로 드래그와 손잡이에서 제외했다.
- 동작 줄이기에서는 손으로 끄는 위치 변화만 반영하고 복귀/퇴장 애니메이션을 생략한다. 도중 설정 변경과 앱 중단에도 남은 변형·타이머를 정리한다.

## 이동과 그리기

- 이동·충돌/착지·짧은 미리보기·재생 중 안내는 브라우저의 `requestAnimationFrame`마다 시간 기반으로 진행한다. 대기 장면은 잔여 시간을 보존하는 30회/초 정책을 유지한다.
- 대기에서 새 이동으로 전환할 때 대기 시간을 첫 이동에 더하지 않는다. 긴 중단의 시간 간격은 기존처럼 50ms로 제한하고, 문서/앱 복귀 때 시계를 초기화한다. 프레임 요청은 하나의 루프만 유지한다.
- 항적은 생성 누적 시간을 사용해 최대 60회/초로 제한한다. 고주사율에서 잔상이 진해지거나 파티클 수가 주사율에 비례해 늘어나는 것을 막는다.
- 가려진 정지 화면은 변경 시에만 다시 그리고 화면 밖 메인 상어·백그라운드의 정지 정책도 유지한다. 이동 시간/곡선, 게임 규칙, 저장 키와 형식, 이미지 해상도와 DPR은 바꾸지 않았다.
- 고주사율에서 짧은 활성 장면의 그리기 횟수는 늘어난다. 실제 GPU 비용·발열·배터리는 실물 기기에서 확인해야 한다.

## 성능 증거

실제 프로덕션 스케줄러에 일정한 가상 화면 시계를 공급한 결과다. 아래 수치는 갱신 호출 수이며 실물 화면의 표시 FPS가 아니다.

| 가상 주사율 | 이전 갱신/초 | 변경 후 갱신/초 |
| --- | ---: | ---: |
| 60Hz | 60 | 60 |
| 90Hz | 45 | 90 |
| 120Hz | 60 | 120 |
| 144Hz | 48 | 144 |
| 165Hz | 55 | 165 |
| 240Hz | 60 | 240 |

데스크톱 내장 브라우저에서 같은 390×844, DPR 1, 첫 수로 R/L 24회, 동일한 현재 셸/자산을 사용해 변경 전후 게임 코드를 비교했다. 일반 동작을 강제하고 기록을 격리한 로컬 QA 화면이다. 계측은 이동 중 JS 그리기 간격과 CPU 호출 시간이며 실제 화면 표시/GPU 측정은 아니다.

| 측정 항목 | 이전 | 변경 후 |
| --- | ---: | ---: |
| 그리기 간격 중앙값 | 18.2ms | 18.1ms |
| 그리기 간격 p95 | 18.8ms | 18.8ms |
| 그리기 간격 최댓값 | 19.9ms | 20.0ms |
| 25ms 초과 간격 | 0 | 0 |
| draw CPU p95 | 0.5ms | 0.5ms |
| 이동 요청→첫 그리기 p95 | 18.1ms | 17.8ms |
| 50ms 초과 Long Task | 0 | 0 |

이 브라우저는 약 18ms 간격으로 콜백을 제공해 기존 제한 문제가 잘 나타나는 90/144Hz 환경이 아니다. 따라서 이 측정으로 체감 FPS가 크게 개선됐다고 주장하지 않는다. 고주사율에서의 불필요한 누락은 가상 시계로 재현·수정했고, 실제 비교 환경에서는 큰 지연이나 악화를 관찰하지 않았다. 입력 지연은 자동화된 이동 요청 이후의 JS 지연이며 실물 터치 지연과 다르다.

## 검사와 재현

- `npm test`: 134개 통과. 실제 시트 핸들러의 거리/속도·취소·복귀·포커스와 실제 스케줄러의 60/90/120/144/165/240Hz·불규칙 간격·대기 후 입력·중단·동작 줄이기를 검사한다. 이동 프레임 간격 20/60/90/144/240Hz에서 최종 위치, 숭어/탈출 이벤트 1회, 항적 수를 확인했다. 기존 생성 취소·진행 복원·특수 장치·보상 검사도 통과했다.
- `npm run verify`: 스토리 48개 및 시험 코스 12개의 해법과 별 기준 통과.
- `npm run build`, `npm run build:artifact`, `npm run build:web`: 통과. `dist/index.html`과 `dist/artifact.html`을 소스와 함께 갱신했다. 외부 의존성은 추가하지 않았다.
- 실제 브라우저 입력으로 9개 시트의 닫기와 구조일지→일일 작전 복귀를 확인했다. 여정/엔딩은 QA의 진입 버튼과 합성 완료 기록을 사용했으며 실제 48개 클리어의 증거는 아니다. 생성 도중 드래그 취소는 핸들러 연결과 기존 자동 검사로 검증했으며 실시간 생성 중 브라우저 재현은 하지 않았다.
- 390×844에서 짧은 드래그 복귀/충분한 드래그 닫기, 320×568 구조일지 스크롤과 헤더 접근, 844×390 안내 본문 스크롤과 확인 버튼, 900×800 중앙 팝업/Tab/Escape를 조작했다. 시트 열린 동안 방향키로 이동 수가 늘지 않았고 닫은 뒤 정상 이동했다. 첫 수로를 실제 키보드 6회로 완료해 별 3개 결과와 다음/다시 하기 버튼을 확인했다.

## 남은 실물 검증과 배포 범위

브라우저 모바일 크기에서 마우스 포인터로 조작했으며 실물 터치, iOS Safari, Android WebView, 실제 고주사율 모니터, 시스템 글꼴 확대, 장시간 발열/배터리는 검증하지 않았다. 실제 기기에서는 헤더 드래그와 본문 스크롤 경합, 빠른 반복 열기/닫기, 이동 중 앱 중단/복귀, 특수 장치 수로의 프레임 안정성을 확인한다.

로컬 소스·웹 빌드·단일 HTML을 갱신했다. 이번 작업에서 공개 사이트 배포, 원격 푸시, Android 동기화/APK/AAB 생성은 수행하지 않았다.
