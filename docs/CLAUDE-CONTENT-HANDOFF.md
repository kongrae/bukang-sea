## R01 경험 순서와 규칙 확정

12판의 초기 편성은 다음을 권장한다. 이는 설계 출발점이며 실제 해법과 플레이 검증 결과에 따라 조정한다.

| 수로 | 지역 | 플레이 의도 |
|---|---|---|
| 1–3 | 북항 | 짧은 성공 경험. 굽은 길·두 공간·갈림길 등 다른 공간 구조 |
| 4 | 북항 경계 | 쉬운 마무리와 다음 수문 시설의 시각적 예고 |
| 5–6 | 수문 시설 | 짧은 장치 예시, 스위치와 수문의 단일 연결 이해 |
| 7–8 | 수문 시설 | 스위치에 먼저 가기, 문 상태를 바꾸고 돌아오기 등 순서 변화 |
| 9 | 수문 시설 | 짧은 휴식 판. 이미 배운 조작으로 빠르게 완료 |
| 10–11 | 수문 시설 | 기존 장치 하나와 수문의 조합, 서로 다른 공간 구조 |
| 12 | 수문 시설 출구 | 배운 규칙을 사용하는 종합 구출과 완료 연출 |

새 장치는 스위치와 수문 한 쌍의 시스템으로 한정하고 첫 시험 코스는 단일 연결 그룹부터 시작한다. 여러 그룹을 넣으면 연결 표식도 추가 제작해야 하므로 임의로 늘리지 않는다.

코드를 바꾸기 전에 다음 규칙을 명시하고 엔진·화면·풀이기에 동일하게 적용한다. 기존 코드와 충돌하지 않는 가장 단순한 방식을 선택하고 선택 이유를 기록한다.

- 스위치가 통과·진입·정지 중 언제 반응하는지, 누를 때마다 토글하는지, 상태가 얼마나 유지되는지.
- 한 번의 스와이프에서 여러 접촉이 생길 때의 순서와 중복 발동 기준. 실제 이동 없는 입력·그물 편집·되돌리기가 새 발동으로 오인되지 않아야 한다.
- 상어 이동, 스위치 상태 변경, 수문 변경, 구조정 이동의 확정 순서.
- 닫히려는 문 위에 상어·구조정이 있는 경우의 처리. 캐릭터가 벽 속에 남거나 사라지는 상태를 허용하지 않는다.
- 열린 수문과 스위치 위의 그물 설치·회수 가능 여부, 기존 물줄기·모래톱·소용돌이와의 겹침 허용 여부.
- 초기 상태, 리셋 상태, 한 턴의 반환 이벤트, 풀이기 상태 식별에 포함할 값, 저장·복원 값.

복잡한 조합은 우선 레벨 검사에서 금지해도 된다. 금지 사항은 명시적으로 검사하고 잘못된 데이터가 조용히 플레이되지 않게 한다. 필수 규칙 결정은 R01에서 끝내고 R02 구현으로 이어간다.

## R02 이동과 진행 호환

- 새 상태가 없는 기존 수로와 기존 함수 호출은 현재와 동일하게 동작해야 한다. 새 규칙을 게임 화면에만 별도로 구현하지 않는다.
- 일반 풀이기와 그물 재배치 풀이기의 상태 키에 수문 관련 상태를 반영한다. 같은 위치·숭어·구조정 배치라도 문 상태가 다르면 다른 탐색 상태일 수 있다.
- 기존 힌트의 그물 회수·설치·이동 안내 계약을 유지한다. 새 장치가 있는 현재 상태에서도 실행 가능한 다음 행동을 안내하며, 수로 변경·되돌리기 시 오래된 검색을 취소한다.
- 되돌리기는 수문·스위치·상어·숭어·구조정·그물 상태를 함께 복원한다. 애니메이션을 건너뛰거나 앱을 중단해도 논리 상태는 일치해야 한다.
- 기존 별·스킨·일일 기록·진행 중 세션을 보존한다. 시험 코스에는 안정적인 수로 ID와 별도 진행 범위를 두어 기존 스토리 번호의 기록을 다른 퍼즐에 잘못 연결하지 않는다.
- 새 필드가 없는 저장 데이터, 맵 서명이 다른 세션, 잘못된 입력 값을 처리한다. 전체 저장 초기화를 마이그레이션으로 사용하지 않는다.
- 장치 첫 등장 예시는 `src/device-demo.js`의 실제 엔진 재생 방식을 확장한다. 가짜 동작을 별도 애니메이션으로 그리지 않는다. 다시 보기·동작 줄이기·확인 기록을 유지한다.

## R03 수로와 시험 코스 연결

기존 48개를 보존한 상태에서 시험 코스 12개를 실제 플레이할 수 있게 한다. 진입점은 기존 수로·여정 선택 흐름 안의 작은 항목 등 현재 UI와 맞는 위치를 선택한다. 메인 화면의 주요 버튼을 무작정 늘리지 않는다. 최종 보고에서 시작 위치를 정확히 알려 준다.

각 수로에 ID, 지역, 학습 의도, 난이도 역할, 맵, 장치 초기 상태, 검증한 해법과 별 기준을 기록한다. 별 기준은 기존 연습·일반·도전 규칙을 우선 재사용하고 실제 엔진의 최단 해법으로 계산한다.

회전·반사나 물체 위치만 바꾼 문제를 연속 배치하지 않는다. 각 판에서 플레이어가 다르게 판단하는 지점을 한 문장으로 설명할 수 있어야 한다. 물리적 구조와 해법상의 선택을 함께 확인한다.

수문을 배우는 핵심 판은 문 상태 변경을 금지했을 때 목표 달성이 불가능한지 별도로 검사한다. 한 최단 경로가 스위치를 지나간다는 사실만으로 장치가 필수라고 주장하지 않는다. 단순 탈출과 숭어 전체 수집 목표는 구분해 기록한다.

## R04 아트와 화면 적용

새 이미지 생성은 Codex 담당이다. 기존 PNG·SVG 원본은 유지하며 `assets/art/content-refresh-v1/README.md`와 `palettes.json`을 따른다. 아트가 추가로 필요하면 용도·크기·상태·대체 표시를 목록으로 남긴다.

- 두 PNG는 지역 선택·예고·전환용이다. 그림에 보이는 건물·배·수로를 실제 퍼즐 칸으로 해석하지 않는다.
- 실제 게임판은 기존 렌더러에서 물색·산책로·난간·시설 장식을 지역별로 바꾼다. 지역 변경은 카드뿐 아니라 플레이 중에도 식별할 수 있어야 한다. 장식이 통행 가능 여부나 장치 표식을 가리지 않게 한다.
- 수문·스위치는 제공된 SVG 4종을 엔진 상태에 맞게 선택한다. 회전·칸 중심·열린 통로의 투명 영역을 유지한다. SVG 지원 때문에 광범위한 렌더러 교체를 하지 않는다.
- 스위치와 수문 상태는 독립적으로 표시한다. 활성 스위치가 언제나 열린 수문을 뜻한다고 가정하지 않는다. 로딩 실패 시에도 실제 상태에 맞는 단순 표시를 제공한다.
- 지역 소개와 다음 구간 예고는 짧게 표시하고 사용자가 계속 진행할 수 있게 한다. 매 판 강제 소개를 반복하지 않는다. 기존 별 획득·구출 연출은 재사용한다.
- 제공 PNG는 제작 원본이다. 기존 sharp 사용 방식을 확인해 카드용 WebP를 새 경로에 만든다. 원본 상어 내보내기를 무조건 다시 실행하지 않는다. 용량·해상도·축소 품질을 보고한다.
- `tools/build-source.js`는 현재 상어 WebP 3종만 내장한다. 새 SVG와 파생 이미지는 단일 HTML·아티팩트·웹·Capacitor에 필요한 방식으로 포함하고, PWA 캐시 해시에 변경이 반영되는지 확인한다.
- 미리보기 HTML·제작 프롬프트·고해상도 원본을 시작 시 로드하는 게임 자산으로 모두 묶지 않는다. 상태 전환은 기존 프레임 루프와 동작 줄이기 설정을 따른다.

## R05 개발 검증과 이용자 확인 준비

기존 테스트 구조에 새 규칙의 핵심 회귀 검사를 추가한다. 최소한 수문 통과·차단, 스위치 재진입, 무효 입력, 구조정과의 순서, 되돌리기·리셋·저장 복원, 힌트 재생, 검색 취소, 예시와 엔진 일치를 검사한다. R01에서 금지한 겹침·데이터도 검사한다.

`npm run verify`가 기존 48개만 대상으로 한다면 시험 코스 12개를 검사하는 경로를 추가한다. 기존 48개 통과를 새 코스의 검증 결과로 대신하지 않는다. 모든 새 해법을 실제 엔진으로 끝까지 재생하고 목표·별 기준·장치 필수성을 확인한다.

필수 실행: `npm test`, `npm run verify`, 새 코스 검증, `npm run build`, `npm run build:artifact`, `npm run build:web`. 빌드에서 폰트 누락 경고가 나오면 기존 폰트 절차로 처리한다. 신규 생성기를 넣는 R07 전까지 기존 일일·자유 버전과 시드를 불필요하게 바꾸지 않는다.

브라우저에서 새 코스 진입 → 북항 플레이 → 수문 첫 예시 → 스위치 발동 → 힌트 → 되돌리기 → 나갔다 이어하기 → 지역 전환 → 최종 완료 흐름을 확인한다. 360px 폭과 짧은 화면에서 가로 넘침·터치 목표·장치 가독성을 확인하고 콘솔·네트워크 오류를 점검한다. 이미지 로딩 실패와 동작 줄이기도 확인한다.

실제 이용자에게는 새 장치 이해 여부, 힌트가 필요했던 판, 반복으로 느낀 구간, 다음 지역을 보고 계속하고 싶었는지를 물을 수 있게 `docs/PLAYTEST.md`의 기존 방식을 확장한다. 빈 양식은 시험 완료가 아니다. 재미 개선·플레이 시간 증가·재방문율 향상을 측정 전 확정하지 않는다.

## 완료 보고와 다음 인수

`docs/CONTENT-PILOT.md`에 규칙 결정, 수로 목록, 완료된 R작업, 테스트 결과, 알려진 한계와 재개 위치를 갱신한다. 컨텍스트가 끊기면 해당 파일과 실제 Git 변경을 확인해 이어서 진행한다.

최종 보고에는 다음을 포함한다.

1. 달라진 플레이 경험과 시험 코스 시작 방법.
2. 12판의 핵심 차이와 수문을 반드시 써야 하는 판의 검증 근거.
3. 기존 진행·일일·자유 호환 검사와 신규 코스 검사 결과.
4. 확인한 브라우저 환경, 확인하지 못한 실물 기기 항목, 실제 이용자 시험 여부.
5. 변경 파일·커밋과 R06 또는 R07 전에 필요한 판단.

커밋은 현재 `CLAUDE.md`의 규칙을 따른다. 소스를 바꾸면 지정된 `dist` 결과물도 함께 반영한다. 무관한 변경과 `.claude/`는 포함하지 않는다. 이번 실행 범위는 로컬 구현·빌드·검증·커밋까지이며, 푸시·Pages 배포·Play Console 업로드는 별도 사용자 지시를 따른다.
