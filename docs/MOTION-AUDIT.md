# 전체 연출 성능·동작 줄이기·중단 점검 — 애니메이션 8번

> 2026-10-03 후속: 아래의 이동 60회/초 제한이 고주사율에서 프레임을 불규칙하게 건너뛰는 문제를 수정했다. 현재는 짧은 활성 이동을 화면 콜백에 맞추고 대기 30회/초를 유지한다. [바텀시트·이동 개선](UI-AND-MOTION-IMPROVEMENTS.md)의 비교·검증 결과를 참고한다. 아래는 8번 작업 당시 기록이다.

2026-10-01. 애니메이션 1–7의 현재 소스를 기준으로 점검했다. 코드·자동 검사·데스크톱 브라우저의 모바일 크기 검증을 완료했다. 연결된 Android 기기가 없어 실물 휴대폰의 성능·터치·진동 검증은 남아 있다.

## 발견한 문제와 수정

- 메뉴 뒤의 정지 화면, 동작 줄이기의 정지 화면도 계속 Canvas에 그렸다. 게임·메인·엔딩에 다시 그리기가 필요한 상태를 표시해 내용 변경·크기 변경·메뉴 복귀 때만 정지 화면을 갱신한다. 메인 상어가 스크롤로 화면 밖에 나가면 그리기와 장식 시간을 멈춘다.
- 높은 주사율 화면의 매 프레임마다 그림을 갱신했다. 실제 이동·짧은 반응·재생 중 장치 안내는 최대 60회/초, 대기 장면은 최대 30회/초로 제한한다. 이는 갱신 상한이며 기기에서 해당 FPS를 보장한다는 뜻은 아니다. 엔딩·물결의 시간도 활성 상태에서만 진행한다.
- 장치 안내는 매번 Canvas의 width/height를 다시 써 비트맵을 초기화했다. 실제 크기가 바뀔 때만 재설정하고, 정지된 안내는 시간·모드·크기 변경 때만 그린다.
- 동작 줄이기를 시작 시 한 번만 읽었다. OS 설정 변경을 즉시 반영하고, 진행 중 턴은 기존 중단 처리로 확정하며 장식·잔상·예시 자동 재생을 정리한다. 안내 손가락과 힌트는 정적으로 남긴다. CSS 애니메이션의 지연도 0으로 만들어 별이나 카드가 늦게 나타나지 않도록 했다. 사용자가 누르는 예시 재생은 계속 제공한다.
- 문서 숨김·페이지 이탈·Capacitor 비활성화 때 프레임 요청을 취소한다. 복귀 때 하나의 프레임 루프만 시작하고 경과 시간을 재설정한다. 문서와 네이티브 상태가 모두 활성화돼야 재개한다.
- 탈출 직후 결과 표시를 기다리는 동안 앱이 중단되면, 별 기록과 결과 표시 요청은 보존하고 남은 소리·진동 타이머만 폐기한다. 복귀 시 결과를 한 번 정적으로 표시한다. 이미 열린 결과는 연출을 반복하지 않고 다음 수로로 진행할 수 있다.

엔진·레벨 배치·보상 조건·저장 형식·힌트 규칙은 유지한다. 동작 줄이기로 전환할 때 진행 중인 이동의 시각적 재생은 끝나지만 해당 턴의 이동·숭어·구조정 결과는 기존 저장 규칙대로 유지한다. 새로운 의존성이나 그림 파일은 추가하지 않았다.

## 자동 검증

- `npm test`: 91개 통과. `tools/motion-audit.test.js`가 실제 스케줄러를 240Hz 가상 시계로 호출해 60/30회 상한, 정지 화면 재사용, 화면 밖 메인, 중복 프레임 방지, 세 가지 중단 상태, 실행 중 설정 변경, 장치 안내 비트맵 재사용을 검사한다.
- 장치 안내를 120번 다시 그려도 초기 width/height 설정 2회가 유지되고 크기를 바꿀 때만 2회 추가된다.
- 보상 검사는 탈출 후 100/650/950ms에 중단한 경우 모두 결과·별을 보존하고 이후 소리·진동 예약을 제거하는지 확인한다. 수로에서 나간 뒤에는 이전 결과를 다시 열지 않는다.
- 기존 이동·저장 복원·장치·보상·메뉴 검사를 함께 실행했다. `npm run verify` 전체 48개 수로 통과. 단일 HTML·아티팩트·테스트·웹 빌드 및 Android 웹 자산 동기화 완료. APK/AAB 생성은 이번 범위에 포함하지 않았다.

## 브라우저 검증

- 390×844 로컬 비교: 수정 전 `386289d` 게임 소스는 설정창 뒤 메인을 17.6초에 534회(약 30.4회/초) 다시 그렸다. 수정 후 설정창이 안정된 다음 초기화한 계측에서 25.5초 동안 추가 그리기 0회였다. 첫 표시와 상태 변경 시 필요한 그리기는 유지한다.
- 장치 안내를 재생하다 동작 줄이기를 켜면 즉시 정지하고 재생 버튼을 표시했다. 이후 17.4초 동안 추가 그리기 0회였고 사용자가 재생을 누르면 정상적으로 재개했다.
- 실제 키보드 6회 이동으로 첫 수로를 탈출한 직후 네이티브 비활성화 경로를 호출했다. 22.9초 중단 동안 Canvas 추가 그리기는 0회였다. 복귀하면 별 3개·6/8회 결과, 다음 버튼 포커스, 배경 입력 차단이 정상적으로 복원됐으며 별 획득 연출을 반복하지 않았다.
- 수정하지 않은 기본 테스트 빌드의 OS 동작 줄이기 상태에서 320×568 그물 안내의 정적 경로·탭·닫기, 힌트 표시, 이동과 되돌리기를 확인했다. 첫 수로를 6회 이동해 별 3개를 받고 다음 수로에 진입했으며 설정을 닫은 뒤 입력과 포커스가 복원됐다. 화면 크기를 줄여도 안내 본문을 스크롤하고 확인 버튼에 접근할 수 있다.

비교 계측은 `outputs/qa/build-motion-audit.cjs`가 생성한 별도 HTML의 화면 내 계측 버튼으로 수행했다. 일반 동작 강제, 설정 변경, 앱 중단 버튼, 후반 수로 개방은 로컬 QA에만 있으며 게임 기록도 격리한다. 비교판은 이전 게임 소스와 동일한 현재 테스트 셸을 사용한다. `outputs/qa/motion8-*.txt/png`에 결과를 보관한다. 계측은 데스크톱 브라우저의 JS 그리기 호출이며 Android GPU·배터리·실제 FPS 측정이 아니다.

## 실물 기기에서 남은 확인

Android 기기 목록은 비어 있었다. 아래 결과는 아직 수집하지 않았으며 출시 전 실제 기기로 확인한다.

1. 저사양/일반 Android에서 스토리 6·12·40번을 10분 이상 플레이하며 스와이프 응답, 구조정·그물·소용돌이의 끊김, 발열을 확인한다.
2. 이동 중, 탈출 직전, 별 1개 표시 직후에 홈으로 나가고 복귀한다. 진행·별 중복, 늦은 소리·진동, 입력 잠김이 없어야 한다.
3. OS 애니메이션 줄이기를 실행 중 변경하고 장치 예시를 수동 재생한다. 하드웨어 뒤로가기와 빠른 메뉴 열기·닫기도 확인한다.
4. 새로 설치한 서명된 앱에서 작은 화면·시스템 글꼴 크기·오프라인 실행을 확인한다. 기기명, Android/WebView 버전, 빌드 커밋, 관찰 시간과 재현 순서를 함께 기록한다.

애니메이션 1–8의 코드 작업은 완료했고, 다음 권장은 이 실물 기기 시험과 기존 `PLAYTEST.md`의 이용자 시험이다. 새로운 9번 콘텐츠 작업을 자동으로 시작하지 않는다.
