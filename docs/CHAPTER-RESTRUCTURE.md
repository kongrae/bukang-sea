# 장 재구성: 장마다 새 장치 하나, 장당 12개

2026-10-07. **상태: 구현 완료.** 계획 단계의 권장안(아래 "결정")대로 반영했다. 저장 형식은 바꾸지 않았고, 화면 순서만 `STORY_ORDER`로 정한다.

## 목표

1. 장마다 대표 장치 하나를 새로 소개한다.
2. 모든 장을 12개로 맞춘다. 6장 × 12 = 72개(기존 60 + 신규 12).
3. 장 안은 학습 → 응용 → 쉬어 가기 → 조합 → 숨 고르기 → 도전의 리듬을 따른다. 장이 바뀌면 다시 쉽게 시작하는 톱니형으로 전체 난이도를 올린다.

기존 60개는 맵·그물 수를 바꾸지 않고 모두 재사용한다. 별 기준이 내려가는 수로는 없다.

## 현재 구성의 문제

`npm run difficulty`와 `src/levels.js` 기준(2026-10-07):

| 장 | 수 | 처음 나오는 장치 |
|---|---|---|
| 1장 북항 수로 | 12 | 부표 2 · 숭어 3 · 구조정 6 · 물줄기 7 · 그물 10 |
| 2장 친수공원 운하 | 12 | 없음(1장 장치 조합) |
| 3장 방파제 너머 | 12 | 없음(1장 장치 조합) |
| 4장 외항 물길 | 12 | 모래톱 37 · 소용돌이 40 |
| 5장 북항 바깥길 | 4 | 없음(장치 없는 부표 수로 4개) |

- 1장은 6–12번 7개 수로에서 장치 3종이 연달아 나온다.
- 2·3·5장은 새로움이 없고, 5장은 장치가 없는 짧은 막간이다.
- 기본(부표·숭어)을 제외한 장치는 6종이고 장도 6개라 1:1 배치가 가능하다.

## 장 안의 칸 규칙

| 칸 | 역할 | 내용 |
|---|---|---|
| 1–2 | 연습 | 새 장치만 단독으로 |
| 3–5 | 일반 | 새 장치 응용, 점점 어렵게 |
| 6 | 일반 | 쉬어 가기: 이전 장치만 쓰는 쉬운 수로 |
| 7–10 | 일반 | 새 장치 + 이전 장치 조합, 점점 어렵게 |
| 11 | 일반 | 숨 고르기·복습: 이전 장치만, 그 장의 도전판보다 쉬움 |

- 1장은 예외로 1–6칸이 기본, 7칸에서 물줄기를 도입하고 11칸이 쉬어 가기다.
- 기존 연습판 49·50·52·57번은 일반 칸으로 옮겨도 **연습 역할을 유지**한다. 역할을 바꾸면 별 기준이 1씩 내려가기 때문이다.
- 이동 수는 사람의 체감 난이도가 아니다. 칸 안의 순서는 1차로 최소 이동·그물 수·장치 수로 정하고, 실제 이용자 시험으로 조정한다.

- 제작 단계 검사:

  - 69번의 구조정은 한 줄만 오가서 수문에 닿지 않는다.
- `npm run verify`는 신규 12개의 벽 구조가 다른 모든 스토리 수로와 다른지, 수문 수로가 수문 변경 없이 풀리지 않는지를 계속 검사한다.

## 저장·진행 호환

진행은 `LEVELS` 배열 인덱스로 저장된다. 영향받는 저장 항목은 `best`, `last`, `storyAccess`, `sessions.story.id`, `sessions.importedStory.id`, `hintUsage['story:N']`, `LEGACY_STORY_LEVELS` 키다. 진행 중 세션의 서명은 맵과 그물 수(`levelSignature`)만 쓰므로 맵을 바꾸지 않는 이동은 세션 복원에 영향이 없다.

### 방식 비교

| | A. 배열 자체를 재배치 + 저장 이관 | B. 배열 순서는 고정 + 플레이 순서표 (채택) |
|---|---|---|
| 방법 | `LEVELS`를 새 순서로 바꾸고, 부팅 시 1회 위 7개 항목을 옛 인덱스 → 새 인덱스로 옮긴다 | 기존 60개 인덱스는 그대로 두고 신규 12개를 배열 끝(60–71)에 추가한다. `STORY_ORDER`(플레이 위치 → 저장 인덱스) 표를 둔다 |
| 저장 데이터 | 7개 항목 재작성. `migratePilotToStory()`와 순서 의존 | 바꾸지 않는다 |
| `CLAUDE.md` 규칙 | "배열 끝에만 추가"를 한 번 어긴다 | 지킨다 |
| 코드 | 인덱스 = 위치가 유지되어 화면 코드는 그대로 | 위치를 쓰는 곳(아래 목록)을 순서표 경유로 바꾼다 |
| 기존 테스트 | 인덱스로 고정한 해법·렌더·힌트 테스트 다수 수정 | 인덱스 기반 테스트는 유지, 위치·장 기반 테스트만 수정 |
| 이후 수로 추가 | 다시 이관 필요 | 장 중간 삽입도 저장 이관 없이 가능 |
| 수로 겉모습 | 장식 시드(`deco = i`)가 바뀌어 모습이 달라짐 | 유지 |

B를 채택했다. 테스터의 실제 진행 기록을 다시 쓰지 않으므로 이관 실수로 기록이 망가질 위험이 없고, 저장은 계속 배열 끝에만 추가한다. 위치와 저장 인덱스의 변환은 `src/levels.js`의 `STORY_ORDER`·`STORY_POSITION`, `src/game.js`의 `storyNext`·`storyLast`·`chapterOf` 한 곳에 모았다.

### 진행 규칙

- **개방**(`unlocked(i)`): 첫 수로이거나, 플레이 순서의 직전 수로를 탈출했거나, 이 수로를 이미 탈출했거나, `storyAccess`에 있으면 열린다.
- **1회 이관**(`migrateStoryOrder()`, `storyOrder: 2`): 이전 순서 규칙으로 열려 있던 저장 인덱스를 모두 `storyAccess`에 더한다. 기존 테스터가 열 수 있던 수로는 계속 열리고, 별은 만들어 내지 않는다. 부팅 시 `migratePilotToStory()` 다음에 실행한다.
- **이어하기**: 플레이 순서에서 첫 번째로 탈출하지 않은 수로다. 기존 테스터는 앞 장에 새로 들어온 수로부터 이어 간다.
- **변경 없음**: 진행 중 세션·힌트 사용·되돌리기 기록은 저장 인덱스를 그대로 쓴다.
- **이전 시험 코스 이관**: `migratePilotToStory()` 루프를 `PILOT_LEVELS` 범위(48–59)로 한정했다. 신규 60–71에는 이전 기록을 옮기지 않는다.
- **별과 스킨**: 최대 별은 180개에서 216개가 된다. 스킨 기준(황금 144 포함)은 유지한다.
- **엔딩**:
  - 72개를 모두 탈출하면 열린다.
  - 재구성 전 60개를 모두 구출한 기록은 이관 때 `storyRescued: 1`로 남겨 메인·여정의 엔딩 다시 보기를 유지한다. 이때 진행 표시는 60 / 72이고, 엔딩 화면은 새 수로를 안내한다.
