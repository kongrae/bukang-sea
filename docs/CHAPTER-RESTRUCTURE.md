# 장 재구성 계획: 장마다 새 장치 하나, 장당 12개

2026-10-07. **상태: 계획(미구현).** 코드·수로·저장 형식은 아직 바꾸지 않았다. 아래 "결정 필요"를 정한 뒤 구현한다.

## 목표

1. 장마다 대표 장치 하나를 새로 소개한다.
2. 모든 장을 12개로 맞춘다. 6장 × 12 = 72개(기존 60 + 신규 12).
3. 장 안은 학습 → 응용 → 쉬어 가기 → 조합 → 숨 고르기 → 도전의 리듬을 따른다. 장이 바뀌면 다시 쉽게 시작하는 톱니형으로 전체 난이도를 올린다.

기존 60개는 맵·그물 수를 바꾸지 않고 모두 재사용한다. 별 기준이 내려가는 수로는 없다.

### 확인한 조건

- 기존 60개가 중복·누락 없이 한 번씩 들어간다.
- 장치가 처음 나오는 위치는 물줄기 7, 구조정 13, 그물 25, 모래톱 37, 소용돌이 49, 수문 61로 장마다 정확히 하나다. 어떤 수로도 아직 배우지 않은 장치를 쓰지 않는다.
- 별 기준은 9개 수로(13·21·18·24·12·34·38·47·44번)에서 1씩 오르고, 내려가는 수로는 없다. 기존 최고 별은 낮추지 않는다.
- 이동 수만 보면 2장 마지막(기존 29번, 17회)이 3장 마지막(11회)보다 길다. 그물 장은 이동이 짧은 대신 배치 판단이 많아서다. 시험 결과 2장 마지막이 과하면 기존 32번(14회)과 맞바꾼다.

## 저장·진행 호환

진행은 `LEVELS` 배열 인덱스로 저장된다. 영향받는 저장 항목은 `best`, `last`, `storyAccess`, `sessions.story.id`, `sessions.importedStory.id`, `hintUsage['story:N']`, `LEGACY_STORY_LEVELS` 키다. 진행 중 세션의 서명은 맵과 그물 수(`levelSignature`)만 쓰므로 맵을 바꾸지 않는 이동은 세션 복원에 영향이 없다.

### 방식 비교

| | A. 배열 자체를 재배치 + 저장 이관 | B. 배열 순서는 고정 + 플레이 순서표 (권장) |
|---|---|---|
| 방법 | `LEVELS`를 새 순서로 바꾸고, 부팅 시 1회 위 7개 항목을 옛 인덱스 → 새 인덱스로 옮긴다 | 기존 60개 인덱스는 그대로 두고 신규 12개를 배열 끝(60–71)에 추가한다. `STORY_ORDER`(플레이 위치 → 저장 인덱스) 표를 둔다 |
| 저장 데이터 | 7개 항목 재작성. `migratePilotToStory()`와 순서 의존 | 바꾸지 않는다 |
| `CLAUDE.md` 규칙 | "배열 끝에만 추가"를 한 번 어긴다 | 지킨다 |
| 코드 | 인덱스 = 위치가 유지되어 화면 코드는 그대로 | 위치를 쓰는 곳(아래 목록)을 순서표 경유로 바꾼다 |
| 기존 테스트 | 인덱스로 고정한 해법·렌더·힌트 테스트 다수 수정 | 인덱스 기반 테스트는 유지, 위치·장 기반 테스트만 수정 |
| 이후 수로 추가 | 다시 이관 필요 | 장 중간 삽입도 저장 이관 없이 가능 |
| 수로 겉모습 | 장식 시드(`deco = i`)가 바뀌어 모습이 달라짐 | 유지 |

B를 권한다. 테스터의 실제 진행 기록을 다시 쓰지 않으므로 이관 실수로 기록이 망가질 위험이 없고, 저장은 계속 배열 끝에만 추가한다. 대신 "위치"와 "저장 인덱스"를 구분하는 규칙이 하나 생기므로 순서표 helper(위치 ↔ 인덱스)를 한 곳에 두고 테스트로 고정한다.

### B 방식의 진행 규칙

- **개방**: 위치 p는 첫 수로이거나, 직전 위치 수로를 탈출했거나, 이 수로를 이미 탈출했거나, `storyAccess`에 있으면 열린다.
- **1회 이관**(`storyOrder: 2`): 현재 규칙으로 열려 있던 저장 인덱스를 모두 `storyAccess`에 더한다. 기존 테스터가 열 수 있던 수로는 계속 열리고, 별은 만들어 내지 않는다.
- **이어하기**: 플레이 순서에서 첫 번째로 탈출하지 않은 수로다. 기존 테스터는 앞 장에 새로 들어온 수로부터 이어 갈 수 있다.
- **변경 없음**: 진행 중 세션·힌트 사용·되돌리기 기록은 저장 인덱스를 그대로 쓰므로 바꾸지 않는다.
- **이전 시험 코스 이관**: `migratePilotToStory()` 루프(`i = 48 … LEVELS.length`)를 `PILOT_LEVELS` 범위(48–59)로 한정한다. 신규 60–71에는 `id`가 없다.
- **별과 스킨**: 최대 별은 180 → 216개가 된다. 스킨 기준(황금 144 포함)은 유지한다.
- **엔딩**: 72개 모두 탈출 기준이 된다. 기존 60개 완료자는 신규 12개를 깨야 다시 완료 상태가 된다(결정 필요 4).

## 문구·표시 수정

| 기존 | 새 번호 | 현재 문구 | 수정 |
|---|---|---|---|
| 12 바다로 가는 길 | 33 | "그물은 두 개까지… 1장의 마지막 도전" | 장 언급 삭제. "그물 두 개" 안내는 처음 그물 2개가 나오는 새 28번(기존 35)으로 옮김 |
| 24 운하의 끝 | 29 | "2장의 마지막 도전" | 장 언급 삭제 |
| 48 먼바다로 | 60 | "외항의 마지막 도전!" | 5장 북항 바깥길에 맞게 수정 |
| 52 북항 끝 부두 | 18 | "저 너머가 수문 시설이에요" (`boundary`) | 문구와 수문 장식 위치 수정 |
| 57 모퉁이 스위치 | 63 | "잠깐 쉬어 가는 수로예요" | 쉬어 가기 칸이 아니므로 수정 |
| 36·28·60 | 36·71·72 | 장 마무리 / 쉬어 가기 / 마지막 구출 | 유지 |

- **여정 문구**(`JOURNEY_STORY`): 장 소개·완료 문구를 새 대표 장치에 맞춘다. 현재 3장 소개는 물줄기·그물, 3장 완료와 4장 소개는 모래톱·소용돌이, 5장은 스위치를 말한다. 2장 소개에는 구조정을 넣는다.
- **판 색**: `setBoardRegion(level.region)`은 수로마다 색을 고른다. 기존 49–52번이 1–3장으로 가면 북항 바깥길 색이 앞 장에 섞이고, 6장에 넣는 기존 28·33번은 수문 색이 빠진다. 판 색과 지역 미리보기의 기준을 장(`CHAPTERS[].region`)으로 바꾸는 것을 권한다.
- **이름**: 1장 "회오리 물길"(기존 15번)은 5장 소용돌이와 헷갈릴 수 있어 이름 변경을 검토한다(선택).
- **안내 기능**: 장치 안내(`DEVICE_GUIDES`)와 첫 그물 안내는 수로에 장치가 있는지로 동작하므로 수정하지 않는다.
