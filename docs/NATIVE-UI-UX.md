# 앱 시작과 모바일 UI/UX 개선

2026-10-14. 기존 게임 규칙·수로·해금·별·보상·저장 키와 세션 형식은 유지했다.

2026-10-15 후속: 메인의 정보 위계와 카드·장식을 더 간결하게 정리했다. 현재 메인 화면과 전후 비교는 [메인 화면 간소화](HOME-SIMPLE.md)를 따른다. 아래 시작 처리·시트·모션 구현은 유지한다.

## 원인과 변경

브라우저에서 확인한 문제:

- 390×844에서 수로 목록을 펼치면 메인의 콘텐츠 높이가 826px에서 1882px로 늘었다. 이제 수로 선택과 게임 방법을 독립된 시트로 열어 메인 구조를 유지한다.
- 시작 버튼, 오늘의 도전·자유 수로, 보조 메뉴가 입체 테두리와 강한 색을 공유했다. 주황색은 플레이·다음 수로 같은 주요 행동에 집중하고 나머지는 밝은 단색과 얕은 그림자로 정리했다.
- 제목의 기울기·굵은 외곽선·반복되는 테두리를 줄였다. 캐릭터와 게임판의 기존 아트는 유지했다. 메인, HUD, 설정, 모드 선택, 외형, 일지, 결과가 공통 표면·버튼 기준을 쓴다.

소스에서 확인한 시작 문제:

- 기존 시작은 `document.fonts.ready`에만 연결됐고 상어 이미지는 따로 도착했다. 이미지 도착 시점과 첫 메인 표시가 연결되지 않았고 글꼴 대기에는 상한이 없었다.
- 이제 `src/launch.js`가 선택한 외형의 초상화·메인 상어·글꼴을 최대 1600ms까지 기다린 뒤 초기화→첫 프레임 그리기→공개 순서로 진행한다. 준비되면 즉시 진행하며 최소 표시 시간은 없다. 늦거나 실패한 자산은 기존 Canvas·시스템 글꼴로 대체한다.
- 게임 초기화·첫 그리기에 실패하면 재시도 버튼을 제공한다. 부팅 요청은 한 번만 실행되고 백그라운드 복귀에 재생되지 않는다.

Android에서 추가로 발견한 문제:

- 첫 에뮬레이터 검사에서 시스템 스플래시와 WebView 사이에 배경만 보이는 구간이 관찰됐다. 기존 AndroidX SplashScreen의 종료 오버레이를 웹 로딩 이미지의 준비 시점까지 유지하도록 연결했다.
- 완전히 가려진 WebView의 애니메이션 프레임을 기다리면 시작이 지연될 수 있어, 네이티브는 HTML 파싱·로딩 이미지의 완료를 기준으로 넘긴다. 메인의 첫 프레임 준비는 웹 게이트가 처리한다.
- 실패 시 재시도 화면도 네이티브 덮개를 해제한다. 렌더러가 응답하지 않을 경우 6초 상한으로 해제하며, Activity 종료 시 검사 콜백을 제거한다. 이 상한은 정상 실행의 고정 대기 시간이 아니다.
- 시스템 테마·WebView·PWA 시작 배경을 `#e8f8f5`로 맞췄다. 기존 상어 WebP를 Android용 투명 PNG로 변환했으며 새 캐릭터나 이미지 생성은 없다. 기존 과거 `splash.png` 파일은 현재 시작 테마에서 참조하지 않는다.

## 조작과 호환성

- 기존 시트의 드래그·포커스·배경 입력 격리·하드웨어 뒤로가기를 재사용한다. 수로 선택→여정→수로 선택 복귀가 연결되고 장 선택·스크롤을 유지한다. 작은 화면에서도 본문은 스크롤하고 닫기 헤더는 유지한다.
- 시작 버튼 연속 탭으로 진행 중 수로를 다시 초기화하지 않는다. 전환 중 뒤로가기 후 한 화면만 남고 입력 잠금이 해제되는 것을 확인했다.
- 메인 등장 320–410ms, 로딩 덮개 페이드 240ms, 기존 화면 push/pop 260/220ms와 시트 모션을 사용한다. 주요 버튼은 덮개 해제와 함께 조작할 수 있다. 동작 줄이기를 존중하고 렌더링 루프는 추가하지 않았다.
- 메인과 새 시트의 동작 상태만 메모리에 보관한다. `bukang-sea-v1`, 저장 버전·이전 로직·소유 외형·모드별 진행 구조는 바꾸지 않는다.
- 기본/아티팩트/웹 빌드와 Android 디버그 APK를 갱신했다. 새 런타임 의존성은 없다. 스토어 버전 번호·서명·출시 트랙은 변경하지 않았다.
- 과거 코드와 비교하는 사운드·모션 QA 도구는 해당 버전의 셸도 함께 사용하도록 보완했다. 과거 런타임에 새 로딩 덮개를 결합해 화면이 가려지는 문제를 피한다.

연결된 실물 기기는 없었다. 에뮬레이터와 브라우저 확인은 실제 손가락 터치, 저사양 GPU·표시 FPS·발열, 실제 시스템 글꼴 확대, iOS Safari 검증을 대신하지 않는다. 브라우저의 pagehide/pageshow 검사는 합성 이벤트였고, Android 홈/복귀는 OS 입력으로 확인했다.

## 비교 자료와 재현

로컬 원자료는 `.gitignore` 대상인 `outputs/qa/native-ui/`에 보관한다.

- `review.html`: 변경 전후 메인·수로 선택·설정·게임, 클리어, 시작 연속 캡처
- `launch-{1-loading,2-reveal,3-enter,4-ready}.png`: 글꼴 요청을 잠깐 보류한 브라우저의 실제 연속 캡처. 제품 코드를 느리게 바꾼 것이 아니다.
- `android-launch.mp4`, `android-seq-*.png`: 에뮬레이터 시작 증거
- `browser-checks.json`, `secondary-screens.json`, `tests.log`, `verify.log`, `android-build.log`: 검증 기록

```powershell
node tools/serve.js . 5182
# http://127.0.0.1:5182/outputs/qa/native-ui/review.html
# http://127.0.0.1:5182/www/
node tools/native-ui-browser-check.js <기존-playwright-모듈-경로>
```

브라우저 비교 도구는 수정 전 `www/index.html`을 `outputs/qa/native-ui/before.html`에 복사해 둔 경우 전후를 함께 촬영한다. 브라우저 저장소는 별도의 테스트 컨텍스트로 격리한다. Android 자산 재생성은 `node tools/prepare-launch-art.js <기존-sharp-모듈-경로>`를 사용한다.

시스템 시작 테마와 종료 처리 기준: [Android 공식 SplashScreen 이전 지침](https://developer.android.com/develop/ui/views/launch/splash-screen/migrate). 실제 프로젝트에 이미 설치된 AndroidX·Capacitor 소스의 API도 확인했다.
