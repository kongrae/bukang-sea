### 문구를 넣은 스크린샷 세트 (2026-11-02 11:25 공개)

2026-11-02 11:15에 Play Console 휴대전화 스크린샷을 이 6장으로 바꿔 검토 제출했고, 11:25에 승인·공개됐다. 업로드 파일 이름은 이전 `6-chapters.png`와 겹치지 않게 `*-caption.png`로 했다. 경과는 `PLAY-CONSOLE-SETUP.md` 진행 상태에 적는다.
- 애셋 패널에서 여러 장을 한 번에 올리면 칸에 자동으로 거꾸로 들어간다. 순서는 하나씩 다시 추가해서 맞춘다.

왜 만들었나:
- 10/20–10/29 스토어 방문자 14명은 전부 Play 탐색에서 들어왔고, 한 명도 설치하지 않았다.
- 지금 올린 세트는 첫 장이 메뉴 화면이고, 어느 장에도 설명 문구가 없다. 그래서 작은 미리보기만 봐서는 무슨 게임인지 알기 어렵다.

- 스토어 등록정보의 '동영상' 칸에 10/23 홍보 쇼츠(세로 1080×1920, 약 25초)를 `https://www.youtube.com/watch?v=4jJO-QH7FjU` 형식으로 넣었다. Console 입력란이 안내하는 형식이고 오류 없이 저장됐다. 13:05에 검토 제출해 13:16에 출시됐다. 쇼츠 주소(`youtube.com/shorts/…`)는 넣어 보지 않았다.
- 미리보기 동영상은 스크린샷 앞에 나오고, 기기에 따라 소리 없이 최대 30초 자동 재생된다. 세로 영상도 지원한다.
- 조건은 공개 또는 일부 공개, 광고 꺼짐, 퍼가기 허용, 연령 제한 없음이다. 11-02 YouTube Studio에서 공개·퍼가기 허용·연령 제한 없음을 확인했고, 채널에 수익 창출 메뉴가 없어 광고를 켠 적이 없다.
- 동영상을 넣으면 그래픽 이미지가 동영상 표지가 된다.

## 데이터 보안 섹션 답변 가이드

- 앱이 사용자 데이터를 수집하거나 공유하나요? → **아니요** (versionCode 10 / 1.9부터. 진행 상황은 기기 로컬 저장소에만 있고 전송되지 않음)
  - 이전 기록: 비공개 테스트 빌드 1.2–1.8(versionCode 3–9)은 `Launchpad.java`가 LaunchPad 품앗이 링크로 설치된 경우에만 Play 설치 참조 문자열을 apptesters.cc로 보냈고, 그동안은 '기기 또는 기타 ID 수집·공유(선택 사항, 앱 기능, HTTPS, 삭제 요청 가능)'로 선언했다. 2026-10-19 프로덕션 출시에 맞춰 코드를 제거하고 '수집·공유 없음'으로 되돌렸다.
  - 설정의 '의견 보내기'와 '문의'(2026-10-26)는 `mailto:`로 이용자의 메일 앱을 열 뿐이고 앱은 아무것도 전송하지 않는다. Play 정의의 '수집'은 앱이 데이터를 기기 밖으로 보내는 것이다. '의견 보내기'가 메일 앱에 넘기는 앱 버전·환경·현재 화면은 이용자가 직접 누른 동작이고 메일에 담길 것을 예상하는 경우라 '공유' 신고 예외(사용자가 시작한 작업)에 해당한다. 그래서 '수집·공유 없음'을 유지하고, 받은 메일의 처리는 privacy.html 6항에 적는다. 앱 안 입력창에서 서버로 보내는 방식으로 바꾸면 보내는 데이터 유형(사용자 생성 콘텐츠, 이메일 주소 등)을 신고하고 privacy.html을 함께 고친다.
- 광고 포함 여부 → **아니요** (나중에 AdMob을 넣으면 데이터 보안 답변과 개인정보처리방침을 함께 바꿔야 함)
