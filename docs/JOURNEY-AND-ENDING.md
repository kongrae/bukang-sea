# 챕터 여정과 구출 엔딩

2026-10-01 콘텐츠 개선 3번. 기존 챕터 완료 문구와 마지막 수로 후 목록 복귀만으로는 구출 작전의 진행과 결말이 드러나지 않아, 장별 상황·탈출 진행도·다시 볼 수 있는 엔딩을 연결했다.

## 플레이 흐름

- 메인 이어하기 아래 ‘구출 여정’에 완료 수로 수를 표시한다. 여정 시트에서 북항 수로 → 친수공원 운하 → 방파제 너머 → 외항 물길의 설명, 통과 여부와 장별 진행도를 확인한다.
- 각 장 목록에 구출 상황과 완료 수로 수를 표시한다. 장의 마지막 수로를 완료하면 다음 장소로 이어지는 문구를 결과에 표시한다. 기존 ‘다음 장으로’는 바로 다음 수로로 이어진다.
- 여정 시트의 장 버튼은 해당 장의 목록을 연다. 잠긴 장도 둘러볼 수 있지만 수로 개방 조건은 그대로다. 기존 진행 중 수로의 이어하기 대상은 바꾸지 않는다.
- 스토리 48개 수로를 모두 한 번 이상 탈출하면 ‘구출 엔딩 보기’가 열린다. 별 144개를 요구하지 않으며 일일 작전 완료는 이 조건에 합산하지 않는다.
- 엔딩에서는 선택한 상어가 좁은 물길에서 넓은 바다로 나아간다. 기존 Canvas 상어·색상·프레임 루프를 재사용하며 4초 뒤 바다 위치에 머문다. 동작 줄이기 설정에서는 처음부터 바다에 있는 정적인 장면을 보여 준다.
- 엔딩의 닫기/Escape/Android 뒤로가기는 열린 출처(최종 결과·여정·메인)로 돌아간다. 수로 목록과 오늘의 구조작전으로도 이동할 수 있다. 메인과 여정에서 언제든 다시 볼 수 있으며, 완료한 사용자의 기본 플레이 버튼은 ‘별 더 모으기’로 표시한다. 진행 중 재도전이 있으면 이어하기를 유지한다.

## 저장 호환

`save.best`의 1~3개 별 기록에서 장별/전체 탈출 수를 계산한다. 저장 키, 수로 순서·인덱스, 개방 조건, 별 판정, 기존 소유·선택 외형, 일일 기록과 세션을 변경하지 않는다. 새 엔딩 완료 플래그는 필요하지 않으며 과거에 모두 탈출한 기록도 즉시 엔딩을 다시 볼 수 있다. 수로를 다시 플레이해도 최고 별은 낮아지지 않는다. 잘못된 별 값 또는 미완료 수로가 남은 기록을 전체 구출 완료로 인정하지 않는다.

## 검증

`npm test` 53개, `npm run verify` 48개 수로, 단일 HTML·아티팩트·PWA 빌드와 Capacitor 동기화가 통과했다. `tools/journey.test.js`는 실제 진행 계산·결과 처리·여정·엔딩·메인 렌더링 함수를 사용해 다음을 검사한다.

- 장 경계와 유효한 탈출 기록, 일일 완료와의 분리
- 별 1개의 장 완료와 다음 장 진입, 기존 별·스킨·일일 세션 유지
- 마지막 탈출 이후 엔딩 진입, 닫기 시 결과 복원, 목록·일일 작전 이동
- 기존 48개 탈출 기록의 재생·재접속, 별 144개 없이 열림
- 앞 수로 누락 시 엔딩 차단, 잠긴 장 미리보기로 개방을 우회하지 못함
- 선택 외형과 동작 줄이기 설정의 정적인 바다 장면

브라우저의 실제 기존 기록(12개 완료/별 36개/스킨 2개)에서 여정·잠긴 4장 미리보기와 기록 유지를 확인했다. 엔딩은 320×568·390×844에서 가로 잘림 없이 표시하며, 짧은 화면에서는 시트를 스크롤한다.

격리된 합성 47개 완료 기록으로 48번 수로를 실제 그물 재배치와 방향키 12회로 완료했다(숭어 4개, 별 3개). 전체 48개 완료/별 50개에서 결과 → 엔딩 → 결과 복귀·목록·새로고침 후 재생·일일 작전 이동을 확인했다. 48개 별 1개만 있는 별도 합성 기록에서도 엔딩이 열렸다. 시험 기록은 `outputs/`의 별도 저장 키/페이지에만 있으며 공개 배포에 포함하지 않는다. 엔딩 장면의 감사용 사진은 합성 기록이므로 스토어 이미지로 사용하지 않는다. `docs/store/9-rescue-journey.jpg`는 실제 기존 기록의 여정 화면이다.

실물 휴대폰 터치와 실제 이용자의 몰입·완주율은 별도 검증이 필요하다. 이번 작업은 새로운 퍼즐 장치·스킨·추가 레벨을 넣지 않는다.
