## R01 스위치·수문 규칙

가장 단순하고 기존 규칙(막힐 때까지 미끄러짐, 상어 이동 후 구조정)과 충돌하지 않는 방식을 골랐다.

### 칸과 연결

| 기호 | 의미 |
|---|---|
| `p` | 스위치. 물 칸이다. 상어를 멈추게 하지 않는다. 구조정은 지나갈 수 있지만 누르지 않는다. |
| `G` | 처음에 닫힌 수문. 닫혀 있으면 벽처럼 상어·구조정을 막는다. |
| `g` | 처음에 열린 수문. 열려 있으면 일반 물 칸처럼 지나간다. |

- 한 수로의 스위치와 수문은 **하나의 연결 그룹**이다. 어느 스위치를 눌러도 모든 수문이 동시에 열림↔닫힘을 바꾼다. 다중 그룹은 연결 표식 아트가 더 필요하므로 지원하지 않는다.
- 수문은 폭 1칸 통로에만 둔다(서로 마주 보는 두 옆이 산책로, 나머지 두 옆은 물, 가장자리 제외). 그림 회전은 이 통로 방향으로 정하고(위아래 통로 = 원본 그대로, 좌우 통로 = 90도) 충돌은 방향과 관계없이 칸 전체로 판정한다.
- 수문이 있으면 스위치가 있어야 하고 그 반대도 같다. 시험 코스는 스위치 1–2개, 수문 1–3개, 판 크기 9×11 이하로 제한한다. 잘못된 데이터는 `parseLevel`(통로·짝)과 `tools/verify-pilot.js`(개수·크기·지역)가 예외/실패로 막는다.

### 상태

- 상태는 연결 그룹의 **누름 홀짝 1비트 `gate`(0/1)** 하나다. 시작·처음부터 = 0.
- 수문 i의 현재 열림 = (처음 열림 `g`) XOR (`gate` = 1). 스위치 그림의 켜짐은 `gate` = 1이다. 스위치 그림과 수문 그림은 각각의 실제 상태로 따로 고른다(`g` 수문은 스위치가 켜지면 닫힌다).

### 발동 시점과 중복

- **상어의 이동이 스위치 칸에서 끝날 때만** 누른다(정지 시 발동). 지나가기만 한 스위치, 출발한 칸의 스위치, 막혀서 움직이지 못한 스와이프, 바다로 탈출한 이동, 그물 설치·회수, 되돌리기는 누르지 않는다.
- 한 이동의 끝 칸은 하나이므로 한 번의 스와이프에서 최대 한 번만 발동한다. 물줄기를 타고 스위치를 지나가도 끝 칸이 아니면 무시한다.
- 누를 때마다 토글한다. 상태는 다시 누르거나 되돌리기·처음부터를 할 때까지 유지된다.
- 선택 이유: 미끄러지는 도중 문이 바뀌면 경로가 상태 변화 순서에 따라 달라져 예측이 어렵다. 정지 시 발동은 "막을 것을 찾아 멈춘다"는 기존 핵심 판단을 그대로 쓰고, 닫힌 수문 바로 앞 스위치는 "문 앞에서 멈추면 열린다"로 바로 이해된다.

### 한 턴의 순서

1. 상어가 **턴 시작 시점의 수문 상태**로 미끄러진다(닫힌 수문 = 벽). 경로의 숭어를 먹는다.
2. 탈출하지 않았고 끝 칸이 스위치면 `gate`를 뒤집는다(모든 수문 토글).
3. 구조정이 **바뀐 수문 상태**로 한 칸씩 움직인다. 닫힌 수문은 벽처럼 방향을 돌리게 한다.

엔진의 `turn()`이 이 순서를 한곳에서 정의하고 게임(`tryMove`)·검증 재생(`replaySteps`)이 그대로 쓴다. 풀이기와 장치 예시는 같은 `slide`→`pressSwitch`→`stepBoats` 순서를 따른다. 화면도 같은 순서로 보여 준다: 상어 도착 → 스위치·수문 전환(0.2초) → 구조정(0.16초). 동작 줄이기에서는 도착 시 최종 상태를 바로 표시한다. 입력은 기존처럼 한 개까지 대기했다가 모든 단계가 끝난 뒤 실행한다.

### 닫히려는 수문 위의 캐릭터

- 상어는 스위치 위에 있어야 누를 수 있으므로 닫히는 수문 위에 있을 수 없다. 복원 검사도 닫힌 수문 위의 상어를 거부한다.
- 구조정이 수문 칸에 있는 동안 그 수문이 닫힘 상태가 되면, 셔터는 **구조정이 빠져나갈 때까지 열린 채 기다렸다가** 빠져나가는 즉시 닫힌다. 그동안 그 칸은 구조정 자체가 막는다. 추가 숨은 상태 없이 `gate`와 구조정 위치만으로 결정되며, 캐릭터가 벽 속에 남거나 사라지지 않는다.
- 닫힌 수문 칸으로는 구조정이 들어가지 못한다. 열린 수문은 지나간다. 이번 시험 코스에는 구조정과 수문을 같은 판에 두지 않았다(검증이 막음). 규칙과 순서는 엔진 테스트로 고정했다.

### 다른 장치와의 겹침

- 한 칸에는 한 가지만 있다. 수문·스위치 칸에는 숭어·시작·출구·부표·물줄기·모래톱·소용돌이·구조정 시작 위치를 둘 수 없다(기호가 하나뿐).
- 그물은 빈 물 칸 `.`에만 칠 수 있으므로 스위치·수문 칸에는 설치할 수 없다(탭하면 장치 설명만 표시). 스위치 너머 빈 칸에 그물을 쳐서 스위치 위에 멈추는 것은 가능하다(p11).
- 물줄기·소용돌이가 닫힌 수문 쪽으로 보내면 기존 벽과 같이 그 장치 칸에서 멈춘다(p10).

### 풀이기·저장

- 탐색 상태 = 상어 위치 + 숭어 + 구조정(위치·방향) + `gate`. 스위치가 없는 수로는 상태 문자열·탐색 순서·양보(yield) 주기가 기존과 같아 일일·자유 생성 지문이 바뀌지 않는다(기존 지문 테스트 통과).
- 그물은 기존처럼 이동 사이에 무료로 재배치한다. 스위치는 이동으로만 눌리므로 힌트의 "회수 → 설치 → 이동" 계약은 그대로다.
- 진행 저장·되돌리기 기록에 `gate`를 넣는다. **스위치가 있는 수로에만** 필드를 쓰며, 기존 수로의 저장 형식은 그대로다. 복원 시 스위치 수로는 `gate`가 0/1인지, 상어가 닫힌 수문 위에 있지 않은지 검사하고, 스위치 없는 수로에 1이 들어 있으면 버린다. 잘못된 세션은 버리고 다른 기록은 건드리지 않는다.
- 한 턴의 반환 이벤트: `turn()` → `{ path, end, win, pressed, gate, boats }`. 화면은 `pressed`일 때 전환 단계를 넣는다.

## R01 진입·진행 설계

- 시험 코스는 스토리 48개와 별도 모드(`PILOT`)다. 수로 ID는 `p01`–`p12`로 고정하고 기록은 `save.pilot = { version: 1, best: { ID: 별 } }`, 진행 중 판은 `save.sessions.pilot` 하나, 힌트 사용량은 `pilot:ID`로 분리한다. 스토리 번호·별·스킨·일일·자유 기록과 섞지 않는다. 알 수 없는 ID·잘못된 별은 그 항목만 버린다.
- 시험 코스 별은 스킨 조건(스토리 별)에 더하지 않는다. 광고·경제·새 스킨은 범위 밖이다.
- 1번은 항상 열려 있고 다음 수로는 앞 수로를 탈출하면 열린다(스토리와 같은 규칙). 플레이테스트 빌드의 `&all=1`에서만 전부 열린다.
- 진입점: 메인 → `수로 선택`를 펼친 목록 안의 작은 항목 `새 물길 시험 코스`. 메인의 큰 버튼은 늘리지 않았다.

## R04-B 아트와 화면 적용

- 장치: `gate-open/closed.svg`, `switch-on/off.svg`를 `tools/build-source.js`가 data URL로 한 번씩 내장한다(단일 HTML·아티팩트·웹·Capacitor 공통, PWA 캐시 이름은 HTML 해시로 자동 갱신). `src/art.js`의 `BOARD_ART`가 타일 픽셀 크기별로 한 번만 래스터화해 캐시하고 매 프레임은 비트맵 복사만 한다.
- 수문은 실제 엔진 상태로, 스위치는 `gate`로 각각 그린다. 전환은 셔터 반쪽이 양쪽 기둥에서 미끄러져 나오는 방식(투명도만 낮추는 대체 없음)이며 기존 프레임 루프에서만 움직인다. 이미지 실패 시 닫힌 수문 = 두 기둥 + 주황 막대, 열린 수문 = 기둥만, 스위치 = 주황 버튼/민트 버튼+체크로 그린다.
- 지역 카드: 원본 PNG(1536×1024)는 그대로 두고 `tools/prepare-region-art.js`(기존 sharp 사용 방식)로 `assets/art/regions/`에 720×480 WebP를 파생했다. 북항 62,860 B, 수문 시설 54,400 B. 3:2 비율 그대로(`contain`) 표시하고 글자는 그림 아래 HTML로 둔다. 실패하면 그림만 숨긴다.
- 게임판: 북항은 기존 표면(스토리와 동일). 수문 시설은 팔레트의 물·바다·산책로·이음선·난간·프레임 색과 산책로 위 배관·계류 기둥 장식으로 바뀐다. 장식은 산책로 칸에만 그리고 통행 칸·장치 표식을 가리지 않는다. p04는 출구 주변 산책로에만 배관을 그려 다음 지역을 예고한다. 상단 라벨 `수문 시설 · 시험 5 / 12 · 연습`과 판 테두리 색으로도 지역을 구분한다.
- 지역 소개·예고·전환: 코스 시트의 지역 카드(그림·이름·목표·진행), p04 결과의 `다음 지역 · 수문 시설` 예고 카드와 `수문 시설로` 버튼, p12 결과의 `시험 코스 완료!`. 매 판 강제 소개는 넣지 않았다. 별·구출 연출은 기존 결과 시트를 재사용한다.
- 장치 안내: `스위치·수문` 예시(6.6초)를 `src/device-demo.js`의 실제 엔진 재생으로 추가했다. 닫힌 수문 앞 스위치에서 멈춤 → 전환 단계 → 열린 수문 통과. 다시 보기·동작 줄이기·확인 기록은 기존 장치와 같다. 설정의 장치 안내는 일곱 장치를 보여 준다.

## 직접 시작하기와 시험 순서

1. `npm run build:web` 후 `npm run serve` → `http://localhost:5173` (또는 `dist/index.html`을 브라우저로 직접 열기).
2. 메인에서 `수로 선택`를 펼친다 → 구출 여정 링크 아래 **`새 물길 시험 코스`** → 지역 카드 아래 `1`.
3. 1–4번(북항): 짧은 성공 → 4번 결과의 `다음 지역 · 수문 시설` 예고와 `수문 시설로`.
4. 5번: `스위치·수문` 첫 안내 → 위로 밀어 스위치에서 멈추면 수문이 열림 → 숭어 → 탈출. 6번에서 "지나가면 안 눌림"을 확인.
5. 7–8번 순서 판단, 9번 휴식, 10번 물줄기, 11번 그물, 12번 갑문 → `시험 코스 완료!` → `코스 목록`.
6. 중간에 되돌리기·처음부터·힌트·뒤로 나갔다가 코스 시트에서 `이어하기`, 설정 → 장치 안내(7개)를 확인한다.
7. 사람 관찰은 `npm run build:playtest` → `npm run serve:playtest` → `?tester=P11`(자연 진행). 수문만 바로 볼 경험자는 `&all=1`(core와 합치지 않음).
